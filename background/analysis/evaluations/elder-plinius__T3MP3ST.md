## 3. Why the design works and its governing invariants

- **Ambiguous side effects get quarantined.** For a nonterminal snapshot, the recovery coordinator treats a persisted in-progress record as indeterminate and records it as blocked without calling the executor. Terminal runs short-circuit, and a lost initial claim admits no action. The revision check is meaningful if the backing store implements atomic compare-and-swap for the requested identity. The clock controls display timestamps. The revision is the consistency token. Key uniqueness in this parser and compare-and-swap in the store cannot establish the executor's effect or its downstream idempotency. [src/mission/recovery.ts:24–27](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:24), [src/mission/recovery.ts:70–89](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:70), [src/mission/recovery.ts:111–113](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:111), [src/__tests__/mission-recovery.test.ts:28–61](repos/elder-plinius__T3MP3ST/src/__tests__/mission-recovery.test.ts:28)
- **A vote cannot silently become a decision.** Within the board, a refutation appends a vote and bumps the card version. Status changes through a separate method. Live claim checks and version checks precede lease publication on one board instance with a synchronous, non-reentrant clock. An expiry sweep removes the lease and preserves a terminal classification. Duplicate records can improve the board's advisory provenance and severity fields monotonically. [src/pack/board.ts:257–319](repos/elder-plinius__T3MP3ST/src/pack/board.ts:257), [src/pack/board.ts:362–413](repos/elder-plinius__T3MP3ST/src/pack/board.ts:362), [src/pack/board.ts:161–183](repos/elder-plinius__T3MP3ST/src/pack/board.ts:161), [src/__tests__/pack-board.test.ts:67–78](repos/elder-plinius__T3MP3ST/src/__tests__/pack-board.test.ts:67), [src/__tests__/pack-board.test.ts:130–215](repos/elder-plinius__T3MP3ST/src/__tests__/pack-board.test.ts:130)
- **Important history outranks the context guideline.** Protected policy, authorization, evidence, citations, unresolved errors, and the current task survive space pressure. The compressor reports their overflow explicitly and gives generated output a lower-trust representation. The source packer makes loss visible through its inventory, elision marker, and body accounting. These are two independent context mechanisms with different units and protection rules. [src/llm/context-compression.ts:66–80](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:66), [src/llm/context-compression.ts:134–147](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:134), [src/llm/context-compression.ts:168–190](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:168), [src/llm/context-compression.ts:210–230](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:210), [src/orchestration/context-pack.ts:31–45](repos/elder-plinius__T3MP3ST/src/orchestration/context-pack.ts:31), [src/orchestration/context-pack.ts:238–253](repos/elder-plinius__T3MP3ST/src/orchestration/context-pack.ts:238)
- **Insufficient execution must remain visible.** Zero recorded calls and a failure ratio of one half or greater yield the degraded verdict. The semaphore reserves a slot before resolving acquisition, transfers a released slot synchronously to the oldest waiter, and makes release idempotent. Its capacity governs simultaneous holders in the current instance. [src/pack/health.ts:56–104](repos/elder-plinius__T3MP3ST/src/pack/health.ts:56), [src/pack/health.ts:139–169](repos/elder-plinius__T3MP3ST/src/pack/health.ts:139), [src/__tests__/pack-health.test.ts:103–149](repos/elder-plinius__T3MP3ST/src/__tests__/pack-health.test.ts:103), [src/__tests__/pack-health.test.ts:198–239](repos/elder-plinius__T3MP3ST/src/__tests__/pack-health.test.ts:198)
- **Optional mirroring has an explicit trust boundary.** An absent configuration produces a controlled result. Configured requests require HTTPS with a matching hostname and manual redirect handling. The remote API returns status and an error class, carrying no provider response body or server key. The migration defines a composite tenant and snapshot key, enables row-level security, and revokes direct access for the `anon` and `authenticated` roles. The module delegates actual tenant authorization, local durability, and schema transaction semantics to its surrounding infrastructure. [src/persistence/supabase.ts:21–41](repos/elder-plinius__T3MP3ST/src/persistence/supabase.ts:21), [src/persistence/supabase.ts:70–96](repos/elder-plinius__T3MP3ST/src/persistence/supabase.ts:70), [src/persistence/migrations.ts:8–25](repos/elder-plinius__T3MP3ST/src/persistence/migrations.ts:8)

## 4. What it does well and poorly, with source evidence

**Recovery has an effective entry guard and an unreliable account of some exits.** The coordinator checks the claim and normal completion CAS results. On post-claim abort and in the failure path it returns the proposed snapshot after discarding the CAS boolean. A caller can receive a cancelled or failed action record while the store still has an in-progress record. A completion write can throw after the action returned a valid receipt. The broad catch classifies this as `execution-failed`, including when the store committed completion before throwing. Reading the journal again can establish the recorded state. An uncertain action effect may still require reconciliation. The in-scope tests cover the initial claim rejection and an already-aborted signal. [src/mission/recovery.ts:70–108](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:70), [src/__tests__/mission-recovery.test.ts:37–73](repos/elder-plinius__T3MP3ST/src/__tests__/mission-recovery.test.ts:37)

**Recovery schema checks field shapes, with weaker checks on relationships between them.** The parser tests unique idempotency keys and the transition code selects by action ID. Repeated action IDs with distinct keys can pass parsing and cause a transition to change more than one record. The JSON-shaped two-record probe executed one inert callback and stored two completed records. A pending action at its attempt ceiling also passes and can produce a claimed snapshot that fails the same schema check after its counter increments. A regex alone coerces a missing or numeric receipt ID into a string for testing and the coordinator can mark the record completed with that original value. Store identity, optional receipt fields, and safe revision magnitude need explicit invariants for a reliable journal. [src/mission/recovery.ts:37–60](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:37), [src/mission/recovery.ts:66–98](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:66), [src/mission/recovery.ts:103–113](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:103)

**Board read copies are strong. Audit publication is weaker.** The board copies incoming coordinates and returns deep copies of cards. Refutations leave status unchanged and the clock seam makes expiration cases deterministic. The raw event is pushed into the log and emitted by reference. Heartbeat state is stored, emitted and returned as the same object. The append-only API therefore offers different isolation depending on the entry point. Log entries also lack information needed to reconstruct the projection. A post records its key and kind without enough fields to reconstruct its title and full coordinates, and a heartbeat event omits the note. A same-status setter call can bump a version without appending an event. The log contains insufficient data for complete replay. [src/pack/board.ts:145–154](repos/elder-plinius__T3MP3ST/src/pack/board.ts:145), [src/pack/board.ts:186–248](repos/elder-plinius__T3MP3ST/src/pack/board.ts:186), [src/pack/board.ts:378–413](repos/elder-plinius__T3MP3ST/src/pack/board.ts:378), [src/pack/board.ts:487–508](repos/elder-plinius__T3MP3ST/src/pack/board.ts:487), [src/pack/types.ts:131–153](repos/elder-plinius__T3MP3ST/src/pack/types.ts:131)

**Context protection and provenance are purposeful. Some budget and identity edge cases are under-validated.** Protected records stay in order and generated summaries carry an input-ID association and escaped data. Summarization failure is visible and leaves the preselected raw window. A NaN summary budget can make the remaining raw budget NaN and silently drop all ordinary records. A custom estimator can return a negative cost for the generated message after input costs already passed validation. Retained records are shared references across the provider await, so external mutation can make input and output accounting describe different values. Generated IDs can also collide with a retained ID, making the returned result fail its own input uniqueness check on recompression. [src/llm/context-compression.ts:92–115](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:92), [src/llm/context-compression.ts:134–147](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:134), [src/llm/context-compression.ts:159–229](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:159), [src/__tests__/context-compression.test.ts:24–54](repos/elder-plinius__T3MP3ST/src/__tests__/context-compression.test.ts:24), [src/__tests__/context-compression.test.ts:73–105](repos/elder-plinius__T3MP3ST/src/__tests__/context-compression.test.ts:73)

**The source map is visible under pressure, including when its estimated cost exceeds the allowance.** The map's internal cap has a floor of 200 estimated tokens, admits the first entry when it exceeds the map cap, and appends an omission footer after the line check. The overall budget may be smaller than the resulting map. In the neutral 30-file fixture, a requested budget of 100 produced 211 estimated tokens with every body omitted. The packing estimate is a character heuristic, and the counterexample holds using that same heuristic. At another boundary, the first elision marker produces one token of estimated overflow. Joining separately priced sections can also put the final estimate above the reported sum. The map also labels a JavaScript string length as bytes. [src/orchestration/context-pack.ts:57–65](repos/elder-plinius__T3MP3ST/src/orchestration/context-pack.ts:57), [src/orchestration/context-pack.ts:186–222](repos/elder-plinius__T3MP3ST/src/orchestration/context-pack.ts:186), [src/orchestration/context-pack.ts:269–319](repos/elder-plinius__T3MP3ST/src/orchestration/context-pack.ts:269), [src/__tests__/context-pack.test.ts:76–109](repos/elder-plinius__T3MP3ST/src/__tests__/context-pack.test.ts:76)

**Local-first ordering contains transport failures. Snapshot identity and receipt lifetime still have gaps.** Local store failure prevents a remote call. A rejected fetch returns a sanitized remote failure after local success. The two clones happen on opposite sides of an await, so a consumer can observe different ordinary values under the same snapshot ID. The pre-transport validation and serializer also sit outside the request catch, so their exceptions can reject the wrapper after local commit. The byte limit accepts NaN through its numeric clamps, which defeats the comparison. Runtime identifier and date validation also depend on JavaScript coercion. The transport timeout requests cancellation, while an injected fetcher must honor that signal. The request clears the timer when fetch settles, and ownership of a nonempty response stream remains unresolved in the adapter. [src/persistence/supabase.ts:44–63](repos/elder-plinius__T3MP3ST/src/persistence/supabase.ts:44), [src/persistence/supabase.ts:70–107](repos/elder-plinius__T3MP3ST/src/persistence/supabase.ts:70), [src/__tests__/supabase-persistence.test.ts:21–64](repos/elder-plinius__T3MP3ST/src/__tests__/supabase-persistence.test.ts:21)

**The health outcome and migration ledger express partial guarantees.** An empty batch is invalid. A call recorded with `ok=true` and empty text counts as successful because `recordResult` checks recognized limit text and trusts the caller's validity flag. A verdict of OK permits some failed work by design. Separately, the migration loop applies known missing versions in registry order. It relies on the backing store to serialize the ledger read and write under contention. Sequential idempotence follows when a successful transaction records the applied version. Concurrent callers can each dispatch the same migration after observing the same starting ledger. [src/pack/health.ts:56–104](repos/elder-plinius__T3MP3ST/src/pack/health.ts:56), [src/__tests__/pack-health.test.ts:114–148](repos/elder-plinius__T3MP3ST/src/__tests__/pack-health.test.ts:114), [src/persistence/migrations.ts:29–41](repos/elder-plinius__T3MP3ST/src/persistence/migrations.ts:29), [src/__tests__/supabase-persistence.test.ts:67–80](repos/elder-plinius__T3MP3ST/src/__tests__/supabase-persistence.test.ts:67)

## 6. Executed tests/experiments and their limitations

The original generic assertion bodies ran in an in-memory Node harness with a narrowly implemented matcher and mock shim. The counted fixtures cover compression (9), packing (10), recovery (6), board (10), health (12), persistence (8), and launch configuration (2). All 57 selected bodies passed in that harness. The shim exercised assertions and supplied dependencies without loading the Vitest runner or executing the application. The board used a reference-preserving Node emitter in place of its package dependency. The persistence probes used injected stores, an inert redaction stub and transport doubles. That establishes coverage gaps in the selected fixtures, with no suite-wide coverage estimate.

## 8. Post-mortem: design pressures, accumulated tradeoffs, likely failure modes, and the highest-leverage improvements

The code favors independent, testable units with optional transports and model providers. The local-first design keeps successful local handling possible when the mirror is unavailable. A separate recovery journal lets an operator inspect ambiguous state. Protection classifications keep important context visible under pressure, and a lightweight board event makes changes observable. These pressures are inferred from the interfaces, defaults, and comments of the reviewed revision. [src/mission/recovery.ts:24–35](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:24), [src/llm/context-compression.ts:66–80](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:66), [src/pack/board.ts:118–154](repos/elder-plinius__T3MP3ST/src/pack/board.ts:118), [src/persistence/supabase.ts:100–107](repos/elder-plinius__T3MP3ST/src/persistence/supabase.ts:100)

The highest-consequence failures occur at handoff points. The recovery code can confuse the state it proposed with the one the store accepted. The board sometimes gives observers references it still owns. The mirror serializes a second view of data after a yield. Compression budgets are calculated before callback and assembly boundaries. The tests are strongest at local transitions with stable data and cooperative stubs. [src/mission/recovery.ts:83–100](repos/elder-plinius__T3MP3ST/src/mission/recovery.ts:83), [src/pack/board.ts:145–154](repos/elder-plinius__T3MP3ST/src/pack/board.ts:145), [src/pack/board.ts:378–383](repos/elder-plinius__T3MP3ST/src/pack/board.ts:378), [src/llm/context-compression.ts:159–224](repos/elder-plinius__T3MP3ST/src/llm/context-compression.ts:159), [src/persistence/supabase.ts:100–107](repos/elder-plinius__T3MP3ST/src/persistence/supabase.ts:100)

Publish a committed snapshot only when the journal confirms it. Treat unacknowledged completion as ambiguous and preserve operator review before repeat activity. Pin the before-commit and after-commit exception cases and both late CAS losses with deterministic fixtures. ## 10. Scoped scoring and conclusions

The 0–10 scale weighs contract clarity, local enforcement and direct boundary evidence. A 10 would require clear invariants and strong evidence for normal behavior and relevant failure paths within the scope. The scores are scoped judgments, with no aggregate for the repository.

| Dimension | Score | Basis |
| --- | ---: | --- |
| Decomposition and maintainability | 7/10 | Narrow pure helpers and dependency injection make important behavior independently reviewable. Several preconditions live only in types and comments. |
| State and audit integrity | 5/10 | Clean admission and card projection boundaries coexist with ambiguous recovery receipts and shared audit references. |
| Context reduction and health accounting | 6/10 | Protected retention, provenance and degraded thresholds are explicit and well supported on valid inputs. Exceptional numeric options and hard-limit assumptions weaken accounting. |
| Persistence and restart contracts | 5/10 | Local-first ordering, opt-in mirroring, and conservative blocking are sound. Returned state, snapshot capture, and atomic migration boundaries leave important consistency gaps. |
| Direct tests and observability | 6/10 | The fixtures cover the main contracts, and deterministic seams allow precise fault analysis. Cases around competing acknowledgements, publication ownership and envelope limits need direct coverage. |

The generic core has clear boundaries for inspection and several strong conservative defaults. The recovery acknowledgement gap and shared audit objects most directly undermine confidence in what a caller sees after a failure. The findings establish those local behaviors at the pinned commit. The excluded workflow, provider behavior, network, database roles and deployment are unscored.
