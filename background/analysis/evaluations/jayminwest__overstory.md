## 3. Why the design works and its governing invariants

1. **A project has one control namespace.** Commands inside the root and ordinary worker worktrees agree on where to read the task and write the inbox, state, and events. The environment and Git-common-dir lookup make separate CLI processes cooperating peers. This is fundamental to using subprocesses and Git as the local orchestration substrate. A stored name is a project-scoped logical address. Parent and run pointers explain causality when role prompts and explicit options use them consistently. ## 9. Post-mortem and highest-leverage improvements

### Likely incident sequence

1. **The original contract fit long-lived tmux workers.** Work was represented by a Git branch and a durable mail address. An agent could sit in its pane while waiting for inputs. Claude's Stop hook was already a turn-level event, so the project had to exempt long-lived interactive coordinators, monitors and leads from completion on that hook. The historical changelog explicitly describes this distinction. [CHANGELOG.md:88](repos/jayminwest__overstory/CHANGELOG.md:88) [src/agents/capabilities.ts:16](repos/jayminwest__overstory/src/agents/capabilities.ts:16) [src/commands/log.test.ts:636](repos/jayminwest__overstory/src/commands/log.test.ts:636)
2. **Headless mode made provider process lifetimes short and put wake-up on the host.** The initial process-era approaches included a local connection registry, then durable plumbing for cross-process mail, then spawn-per-turn. The supported task roles expanded beyond builders, including leads with ordinary wait-for-child turns. The published design tells those leads to end a turn after dispatch. The same model lifecycle event therefore now spans harmless wait, failure and actual assignment completion. [CHANGELOG.md:132](repos/jayminwest__overstory/CHANGELOG.md:132) [CHANGELOG.md:196](repos/jayminwest__overstory/CHANGELOG.md:196) [agents/lead.md:57](repos/jayminwest__overstory/agents/lead.md:57)
3. **A timeout symptom was resolved locally by promoting an ambiguous clean result into completion.** The changelog says the aim was to stop clean exits with missing terminal mail from staying active forever. Runner-side `worker_died` made those exits visible to parents. That change treated a missing terminal message as failure across capabilities, while the dispatcher treats completed as ineligible. The reliability improvement for a one-shot worker became a permanent wake-up failure for a healthy multi-turn lead. The control observed the full sequence, including the refusal of the child's late reply. 4. **Additional substates improved visibility while leaving a hidden persistence edge.** Version 0.11 added `in_turn` and `between_turns`. The regression test verifies mid-turn SQLite state and the calculation it returns, while the final guarded write depends on a now-stale entry-state comparison. A misplaced read at a test boundary lets a state-machine defect survive strong coverage and a passing suite. Meanwhile each watchdog iteration defers to observed signals opportunistically and still has partial awareness of the direct-turn PID. 5. **Integration and cleanup favor getting unstuck at the project root.** Auto-stash, state-file commits, untracked-file deletion and final `-D` calls minimize common merge/cleanup friction.
