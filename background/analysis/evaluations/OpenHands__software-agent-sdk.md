## 2. Core architecture and end-to-end control/data flow

### Construction and ownership

The monorepo packages four different responsibilities. `openhands-sdk` defines the typed agent, conversation, model, event store, and local/remote workspace protocols. `openhands-tools` registers concrete tool definitions, tool sets, providers of built-in agent presets, and resource-owning executors. `openhands-workspace` supplies API, container, and other remote workspace implementations. `openhands-agent-server` hosts the local SDK runtime per conversation and exposes lifecycle, event, and workspace APIs. Client-side `Conversation(...)` selects `LocalConversation` for a path or local workspace and `RemoteConversation` for a remote workspace. Execution is local to the selected runtime, so normal tool executors always receive a `LocalConversation`, including jobs launched over HTTP. [Repository boundaries](repos/OpenHands__software-agent-sdk/AGENTS.md:28), [Conversation factory](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/conversation.py:155), [Executor contract](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/tool/tool.py:283), [Server construction of LocalConversation](repos/OpenHands__software-agent-sdk/openhands-agent-server/openhands/agent_server/event_service.py:1431).

Construction establishes a UUID, workspace, file store, runtime state, and per-conversation LLM registry. Opening existing state can use the stored agent or an explicitly supplied compatible agent. Native initialization is lazy and idempotent within one conversation. On the first input or run it loads plugins, reads project/user agent definitions, materializes `Tool` specs into executors, attaches runtime MCP tools, initializes the system prompt, and registers model usage roles. ACP launch is deferred until run since provider startup may be expensive. The launch pipeline separately resolves request/profile/settings inputs, previews the resolved capabilities, and finalizes runtime-dependent contributions for the server's actual execution environment. It centralizes launch policy across consumers while keeping runtime I/O out of preview. [State open-or-create](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/state.py:615), [Conversation-owned call context](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:413), [Lazy initialization](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2001), [Resolve launch inputs](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/launch/resolve.py:86), [Preview launch](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/launch/preview.py:33), [Finalize runtime launch](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/launch/finalize.py:64).

### One native turn

1. `send_message()` normalizes a string to a user `Message`, attaches per-turn context, and emits a `MessageEvent` under the state lock. The event chain applies hooks and tree bookkeeping, writes the event, then invokes persistence-dependent external callbacks. It tracks the latest real user message ID for the next step. New input can reopen a finished or stuck conversation. [Event callback ordering](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:518), [User input](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2348).
2. `run()` or `arun()` owns the step loop, status transitions, stop hooks, iteration limit, cost checks, and stuck handling. A second run through `WAITING_FOR_CONFIRMATION` counts as approval for the pending calls. Rejecting writes observations linked to the actions. The usual async branch releases all FIFO lock levels around the main model wait, then compares the latest user ID to its pre-step snapshot. If new input landed before a finish, it can continue or leave the conversation idle at the iteration limit. It rejects pending confirmation from a superseded reply before continuing. The sync branch uses FIFO admission between steps to let waiting user input run. [State-lock release scope](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2524), [Sync run](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2581), [Async native step and input rescan](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2940), [Reject pending actions](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:3356).
3. The agent executes unmatched prior actions first. Otherwise it reads the active branch's cached `View` and optionally runs a condenser. Condensation is itself an event and may finish this step without a main-model call. The projection rebuilds an assistant tool-call message from consecutive actions belonging to one response. It preserves the system lead-in and normalizes the request tail. The native path calls `LLM.generate/agenerate` with projected messages and the active tool schemas. [Async agent step](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/agent/agent.py:1082), [Projection and condensation](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/agent/utils.py:600), [Event-to-message projection](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/event/base.py:109), [API selection](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/llm/llm.py:1885).
4. The model boundary formats Chat Completions or Responses requests with provider capability normalization and converts the response into SDK `Message`, metrics, and raw-response metadata. The agent classifies text, tool calls, reasoning-only, and empty output. Plain text emits an assistant message and proposes `FINISHED`. Tool-call responses become typed actions or correlated corrective errors. Empty and reasoning-only turns can receive a corrective nudge. Malformed provider history and context-window overflow have separate recovery signals and can re-enter through a condenser. [Async generation dispatch](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/llm/llm.py:1917), [Model dispatch and recovery](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/agent/agent.py:1167), [Tool-call dispatch](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/agent/response_dispatch.py:204), [Text and empty response handling](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/agent/response_dispatch.py:260).
5. Tool validation maps call arguments into typed actions. The batch applies blocking decisions and termination rules, runs tools using the resource lock manager, and emits observations/error results in original action order after collection. Each result has action and/or provider tool-call identity. A separate finalization phase can mark the conversation finished or request refinement. Native parallelism is bounded per batch and can be restricted further by tool-declared resource keys. State and workspace side effects are only partially coupled, as §5 shows. ### State, resumption, and remote transport

`ConversationState` today combines an append-only log, a mutable checkpoint, and a derived model view. The log persists JSON event files keyed by a durable sequence in the filename and stable event IDs. Parent IDs link facts into a tree. `leaf_event_id` selects a branch and `head_is_empty` expresses a deliberate new root. The chronological store retains abandoned branches. Cold open validates `base_state.json`, indexes the log, repairs a missing head, and rebuilds the view with consistency checks. A healthy append replays only the newly relevant tail into the cached view. Fork creates a new conversation and agent object graph, copies the selected path or full history, and applies an independent checkpoint. Workspace identity can remain shared. The server's `ConversationService` keeps persisted records apart from loaded `EventService` instances. Lifecycle operations use per-conversation locks and a broader exclusive operation for cache-wide tasks such as eviction. `EventService` uses an asyncio run-admission lock, a server-level run semaphore, per-run task tracking, and a per-conversation state-operation executor. It prefers native async implementations and wraps sync extensions in a dedicated executor. A reference-counted session permit can span continued runs or goal activity. Leases provide an on-disk owner and generation with renewal and guarded writes. Idle eviction can close live executors and reload an event service later using the persisted config. Server restore treats a saved `RUNNING` state as stale after ownership has been established and can pair a discovered interrupted action with a synthetic recovery result. The Python remote client sends REST commands, maintains a WebSocket subscription and cached `RemoteState`, and reconciles durable events over REST after reconnect, timeout recovery, or run completion. A per-field `FINISHED` is provisional because stop hooks can change the outcome. The final full-state notification follows the run and a pending-callback drain. Stuck handling belongs to the native run controller. Its detector can inject one corrective environment message for a repeating action-error streak, then apply pattern detection and transition to `STUCK`. The optional server goal loop operates above ordinary run admission. It waits for each agent run, snapshots the event log under the state lock, and hands the transcript to a judge on a worker thread after releasing the lock. A pending user question stops the loop without judging. The judge can complete the goal or generate a follow-up, subject to a separate round cap. A stuck round can reach the judge. A paused or errored round ends the loop. Interruption is recorded in a goal-status event and the session permit is released in cleanup. ### Streaming, delegation, and the execution environment

Token chunks flow from transport through the agent's `StreamContext`. The raw callback path provides the legacy transient deltas. The session socket has a separate started/delta/aborted stream with minted item IDs, attempt and order markers, and a durable assistant event that retires the slot. It buffers live durable events during replay, uses `after_seq` as an exclusive resume boundary, deduplicates at the replay watermark, and drains a bounded writer queue with one task. Progress is transient and reconnect is principally recovery of durable facts. Slow writers can be disconnected and resume via cursor. It resolves a registered factory, instantiates a child agent and conversation with its own config/metrics/history and parent workspace, runs it to a terminal state, returns a typed parent observation, rolls its usage into the parent, and evicts the live child. The agent server separately supports a linked child conversation with a fresh event history and optional Git worktree, reserved against server run capacity before creating files. ## 4. Strengths

- **Events carry operational meaning.** The separation among durable history, active branch, and provider-facing messages supports replay, branch navigation, and condensation without rewriting original evidence. Status, ACP progress, history edits, typed errors, model requests, and tool results can be consumed according to their role. Cold load tolerates gaps and malformed individual event payloads with useful diagnostics and keeps later sequences usable. [Unreadable-event recovery](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/event_store.py:252), [Sparse index reconstruction](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/event_store.py:466), [View derivation](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/context/view/view.py:148), [Gap recovery tests](repos/OpenHands__software-agent-sdk/tests/sdk/conversation/test_event_store.py:682).
- **The hot path makes useful latency and compatibility choices.** Native LLM calls suspend rather than monopolizing a worker thread, model-I/O lock release lets user input through, and the controller rechecks for a concurrent follow-up. ## 6. Core-code quality

**Decomposition and extension ownership.** The controller/agent/tool/model separation holds across local and remote use. Types expose good seams: `AgentBase.step/astep`, `Tool` spec factories, tool-schema validation, recognized Pydantic event subclasses, `MCPToolProvider`, `FileStore`, workspace implementations, and condensers. The concrete local conversation, LLM, and service modules still carry several state machines and compatibility paths each. `LocalConversation` includes plugin lifecycle, late MCP, branch control, two loops and a separate ACP async track. `LLM` combines transport choice, formatting, retry, model metadata, observability, and sync/async implementations. The useful seams can be retained while extracting one explicit lifecycle owner for each kind of mutable resource. [Agent lifecycle interface](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/agent/base.py:546), [Typed executor API](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/tool/tool.py:283), [MCP materialization and lifecycle](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:1651), [Async controller split](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2794), [Model transport implementations](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/llm/llm.py:1953), [Server run lifetime](repos/OpenHands__software-agent-sdk/openhands-agent-server/openhands/agent_server/event_service.py:1610).

**State and concurrency.** A FIFO state lock, copied execution context in tool-worker threads, leased storage ownership, bounded server admission, and deterministic result assembly are good mechanisms. The mixed sync/async ownership rules remain delicate. `FIFOLock` is reentrant by OS thread, so state-mutating coroutine callers on the same event-loop thread can re-enter. The ordinary server funnels such work through the state executor. Model I/O temporarily releases both lock depth and deferred-save depth; returning synchronously reacquires the thread lock. The model-switch tool has an explicit exception to lock acquisition so it can mutate the conversation from a worker when the step is waiting on that worker. These exceptions make reviews of new mutators harder. A conversation-owned serialized state lane plus an immutable run/step generation would reduce dependence on thread location. [Lock model](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/fifo_lock.py:14), [Release/reacquire](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2524), [Tool mutation exception](repos/OpenHands__software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py:2157), [State mutation executor](repos/OpenHands__software-agent-sdk/openhands-agent-server/openhands/agent_server/event_service.py:334), [Run lock](repos/OpenHands__software-agent-sdk/openhands-agent-server/openhands/agent_server/event_service.py:1636).

**Errors and retries.** The runtime distinguishes corrective tool errors, provider failures, resource lock timeouts, intentional interrupts, a stuck policy, and lifecycle errors. Retry is appropriately centralized in the LLM layer with context failure delegated to the agent/condenser. The SDK and remote API expose different run-error conventions, so a status-only caller and an exception-only caller need different checks. Run cost is evaluated from combined conversation metrics at step boundaries, with a finishing step carve-out. ## 9. Post-mortem and prioritized improvements

The architecture supports an embedded synchronous SDK and a shared asynchronous daemon. It accommodates third-party executors that can be synchronous, long-running, and effectful. It preserves deployed histories while adding tree navigation and durable cursor replay. It also hosts an external ACP lifecycle alongside native tool execution. The defects concentrate at those boundaries. An event and its selected lineage commit separately. A frozen model also owns a live tool map. Cancelling the asyncio task and settling its workers have different guarantees. Terminal policy is applied at distinct points in the sync, native async, and ACP loops.

1. **Commit durable lineage and action outcomes under one recovery contract.** Use an append/commit record or a transactional store that advances head and records explicit navigation in the sequence containing the relevant events. Preserve event IDs, wire cursors, and legacy read behavior. Track which input was acknowledged, what effect was observed, and what outcome remains uncertain. Test abrupt exit before append, after append before checkpoint, and after a tool effect before observation. Include deliberate rewind in every head-repair regression suite.
2. **Split reusable configuration from runtime resources.** Materialize a runtime agent or binding per conversation and put its executors, MCP sessions, and initialized flags there. Give partial factory initialization an explicit rollback scope. Keep LLM configuration reusable and retain per-usage session identities. Test simultaneous startup with one shared config and two workspaces, then close each independently. Reserve a generation per child task resume, document and persist the child ID mapping if it must survive eviction, and apply the same child limits on create and resume.
3. **Give cancellation a complete lifecycle.** Track one run generation across startup, model wait, hooks, tool execution, observation commit, and cleanup. Move parallel executor drain off the server loop and keep the generation's cancellation token attached to its workers until termination. Preserve known successful outcomes before marking the remaining in-flight work uncertain. Prevent a successor from using still-draining resources. Validate request liveness and admission with cooperative executors that need time to release resources.
4. **Share terminal decision policy across run lanes.** Keep the separate sync and async transports and a common termination decision step. Define stop-hook precedence at an exhausted iteration cap. Execute blocking hooks off the event loop, then serialize their decisions onto the state owner. Publish a run-generation completion fact with its terminal reason so transport clients can wait for a specific run.
5. **Use a common durable sequence API and measure resources at the right boundaries.** Derive stream anchors, replay cursors and cutover positions from the same sequence function. Cache fallback profile resolution by configured identity or index. Track unresolved workers, callback drain backlog, replay gaps, and child runs in observability. Bound the decoded-event cache or document a retention policy. Measure cold rebuild and steady-state step work separately.

The useful contracts to preserve are typed tools and observations, stable durable replay, provider error classification, deterministic normal batch results, per-role metrics, and server run admission. Tests spanning event commit, checkpoint save, external effect, and run termination have the highest leverage because the individual components can each pass while their combined lifecycle loses information.
