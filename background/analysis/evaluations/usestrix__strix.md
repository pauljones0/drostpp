## 3. Why the design works and its governing invariants

- **One coordinator per active run and one driver per node.** The coordinator lock orders graph and wake mutations within a loop, and a per-session mutex orders application-side writes through the same session object. A receiver checks its wake predicate and clears its event under the same lock a sender takes to enqueue and set it. That ordering closes the ordinary send-before-wait race with minimal scheduler machinery. The mutex is keyed by Python session object, so a second handle to the same logical history has its own mutex. The implementation relies on application callers maintaining one recording driver per agent ID. [strix/core/agents.py:59](repos/usestrix__strix/strix/core/agents.py:59) [strix/core/agents.py:441](repos/usestrix__strix/strix/core/agents.py:441) [strix/core/agents.py:473](repos/usestrix__strix/strix/core/agents.py:473) [strix/core/sessions.py:89](repos/usestrix__strix/strix/core/sessions.py:89) [strix/core/execution.py:1175](repos/usestrix__strix/strix/core/execution.py:1175)

- **A state change carries lifecycle meaning.** Successful tool responses and explicit coordinator state govern termination. A normal text response while the state remains running triggers bounded recovery. Failed interactive agents require an operator wake in live memory. That makes UI disconnection and provider errors recoverable without treating a normal assistant message as an acknowledgement of completion. The budget epoch lets the driver detect a resume that lands before it waits and checks stopped state before transitioning a parked agent. ## 9. Post-mortem

The source fits a CLI that wants quick startup, rich local diagnostics and a small local runtime footprint. The SDK supplies model turns and session primitives. The run coordinator hosts active workers as tasks with separate session IDs. Strix adds a model-directed control plane, a small graph store, workspace ownership and output persistence around it. On this shape, the easiest implementation for each new concern is one more lifecycle field, a callback around an SDK feature, or a separate file. That creates fast iteration and straightforward single-run debugging. Over time, the wrapper becomes responsible for cross-layer consistency that each component can only partially see. This is an inference from the current implementation and its comments. The shallow checkout cannot establish the order in which earlier choices accumulated. **Make operator control dominate execution.** The first boundary to harden is any handoff that can issue work after a stop or pause. Both the peer-wait timeout and retry backoff can resurrect a stopped state. A caller-cancelled MCP queue entry can dispatch after its consumer exits. Budget hooks guard main SDK calls, while context compaction may reach the provider first. Use an authoritative per-run cancellation state checked at handoffs and before side effects. Preserve a terminal status in destructive cascades. Require an explicit new authorized transition to reenter running when a caller resumes.
