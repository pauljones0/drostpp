IronCurtain has a compact state-machine model and strong seams for agent and MCP execution. Its reliability limits show up where an operation changes owners across an `await`. A job can be executing after the client receives a timeout, a workflow can finish aborting while a session factory still owns unfinished initialization, and a session can overwrite its closed state after a late response. The most useful changes would connect command acknowledgment, worker admission, cancellation, and terminal publication to the same durable identity.

## 2. Core architecture and end-to-end control and data flow

**Entry points and control plane.** `ironcurtain start` resolves the requested session mode, workspace, persona and model, then constructs a transport and session. `createStandaloneSession` mints or restores the CLI conversation identity for an external agent and delegates to `createSession`. The daemon composes a `SessionManager`, cron scheduler, optional Signal adapter, and local control socket. The socket uses one newline-delimited JSON request and response per Unix connection. Workflows have a separate `WorkflowController` API. The stand-alone CLI owns an orchestrator in-process, and daemon-backed commands talk JSON-RPC over WebSocket to the server-side workflow dispatch and its `WorkflowManager`. Those two RPC surfaces have different timeout and result contracts. `workflow await` subscribes before its first authoritative `get`, then repeats `get` on a matching lifecycle event. `interrupted` represents a persisted run with no live actor to emit events. (`src/index.ts:122–203`, `src/session/index.ts:120–132`, `src/daemon/ironcurtain-daemon.ts:95–105,152–237,746–765,796–808`, `src/daemon/control-socket.ts:1–17,182–225`, `src/workflow/workflow-manager.ts:135–175,399–432`, `src/daemon-client/daemon-client.ts:76–108,139–193`, `src/workflow/daemon-gate-commands.ts:587–650`, `WORKFLOWS.md:396–406`.)

**Definition to graph.** YAML loader disables alias expansion and permits JSON as an internal definition-copy format. The manifest goes through raw-field checks, a Zod discriminated union, and semantic checks for transitions, required artifacts, verdict declarations, scope and lane constraints. `start()` also checks personas and workflow skill references. It creates a run ID, writes the workspace task description, copies the validated definition and stages package skills and scripts into the run directory. `buildWorkflowMachine` maps agent and deterministic states to promised actors, gates to event-driven states, and terminals to XState finals. It compiles ordered guards or exact verdict matches and combines the built-in context update with authored transition actions. Invoke errors initially favor a reachable review gate, then a failure-like terminal, then another terminal. The parent context carries artifacts, round and visit counts, last output/error and conversation identity. **Turn and artifact handoff.** The orchestrator builds a state prompt from task context, prior output, human feedback and input/output artifacts. It creates a new session for the invocation. A state with `freshSession: false` can reuse the stored external conversation ID, while run, bundle, invocation and session identities retain separate lifecycle roles. ## 3. Why the design works and its governing invariants

1. **Control state is explicit.** Models supply results and artifacts. The definition determines transitions, validation decides whether a shape is legal, and XState runs the graph. Keeping the parent state value scalar lets gates, current-state reporting and checkpoints share a simple state address even when a child segment is concurrent. Parent transitions apply structured result updates before authored actions. (`src/workflow/machine-builder.ts:279–323,399–437,594–638`, `src/workflow/orchestrator.ts:2966–2987`.)
2. **Identity follows the owned object.** A run owns the state graph, a bundle owns transport and container resources, a session owns an invocation, and a conversation ID identifies the external transcript to reuse. A shared `SessionManager` label allocator prevents collisions between managed transports and workflow-owned agent labels. Container snapshots are associated with a scope within a run and have independent identities. (`src/session/session-manager.ts:90–125`, `src/docker/docker-agent-session.ts:62–107`, `src/workflow/orchestrator.ts:1017–1024,2462–2494`, `src/workflow/container-snapshots.ts:49–72`.)
3. **Policy authority stays centralized.** One coordinator owns decision, approval, and audit state. Shared-container starts await policy-load acknowledgment, and the persona cache is invalidated before the call so an ambiguous response cannot turn into an incorrect cache hit. Load constructs the replacement before publication. The fan-out pump enforces one shared scope at runtime, and the bundled evolve design assumes one persona for the batch. The validator checks lane membership and result-file scoping. (`src/workflow/orchestrator.ts:1164–1214,3026–3027,3337–3366`, `src/workflow/validate.ts:480–515,555–633`, `src/trusted-process/tool-call-coordinator.ts:333–391,565–624`, `docs/designs/evolve-sync-parallelism-slice.md:596–606`.)
4. **Replay starts from durable handoff boundaries.** Run data and the staged definition are independent of the originally selected package pathname. The checkpoint deliberately keeps the last nonterminal state for replay. Progress between durable checkpoints is repeatable work unless the external service has its own idempotency record. The evolve recorded-lane rule is a specific application of that distinction. (`src/workflow/orchestrator.ts:1576–1586,1675–1686,1835–1921,2251–2257,3386–3408,4714–4721`.)
5. **Individual cleanup paths make progress despite ordinary failures.** Session construction has rollback, the bundle teardown starts once and is joinable, and peer outcomes are retained across child failures instead of discarding the whole barrier’s evidence. These invariants have a limited domain. The complete end-to-end abort and ownership contracts still have gaps described below. (`src/session/index.ts:411–435`, `src/workflow/orchestrator.ts:1053–1104,1243–1304,3125–3153,3943–3962`, `src/docker/docker-infrastructure.ts:1940–1971,1988–2040`.)

## 4. Strengths

- **Good seams for causal tests.** `WorkflowOrchestratorDeps` exposes the session factory, checkpoint store, gate/lifecycle sinks, runtime factories and policy RPC. `ContainerRuntime`, `AgentAdapter` and `Session` make integration ownership visible. The existing tests exercise CLI command assembly and response parsing, mocked container lifecycle, budgets, checkpoint behavior and persistence without relying on model nondeterminism. (`src/workflow/orchestrator.ts:586–654`, `src/session/types.ts:627–712`, `src/docker/types.ts:315–360`, `src/docker/agent-adapter.ts:223–346`, `test/docker-agent-session-retry.test.ts`, `test/workflow/validate.test.ts`, `test/docker/resource-watchdog-supervisor.test.ts`.)
- **Bounded recovery distinguishes outcome classes.** Returning a routable verdict, retrying status framing, recovering an unusable conversation, and pausing for upstream recovery receive different log entries and control effects. Conversation rotation and persistence are explicit, so intentionally abandoned identities need not be reused as though their transcripts were durable. Artifact handoff is constrained to a configured validator edge with required output files. (`src/workflow/orchestrator.ts:2586–2631,2676–2882,4646–4695,4787–4810`, `src/workflow/validate.ts:695–787`, `src/docker/docker-agent-session.ts:424–481`.)
- **Availability is designed into resource composition.** Lazy infrastructure avoids a container dependency for gate-only or host-only startup. Known failure seams tear down the partial bundle, coordinator startup failure can trigger cleanup before map publication, mismatched server requirements are rejected before session execution, and a separate nested-workload supervisor has stronger failure recovery than an in-process callback alone. - **Useful failure evidence.** Atomic checkpoint save, explicit terminal phase, resume fingerprint, and the message journal give an operator several corroborating observations. The SQLite metrics worker uses an explicit schema and WAL; owned leases make last-user shutdown and retention scheduling testable. The tested provider proxy and metrics suites cover synthetic streams, malformed input and bounded shutdown without live provider traffic. ## 6. Core-code quality

- **Decomposition and extensibility.** The type-level seams are productive. The built-in adapter registry uses an explicit static map with duplicate registration checks and enumerates Claude Code, Goose, and Codex. Adapters specialize image, setup, CLI command, provider/env and output parsing. The runtime factory selects a capability-bearing Docker or Apple implementation. MCP onboarding is configuration and generation of policy artifacts. Workflow extension uses validated manifests and packaged skills/scripts. Internals that are injectable in tests do not imply automatic runtime adapter discovery. (`src/docker/agent-registry.ts:1–59`, `src/docker/agent-adapter.ts:223–346,422–471`, `src/docker/container-runtime.ts:57–97`, `src/docker/types.ts:315–360`, `ADDING_MCP_SERVERS.md:1–105`, `src/workflow/discovery.ts:49–89,198–216`, `src/workflow/orchestrator.ts:1576–1586`.)
- **State, types and errors.** Discriminated input/output types, typed error codes and branded IDs are good tooling choices. Parsing at the definition boundary is stronger than the restore boundary. XState `AnyStateMachine` and string-built internal event names make restart behavior a version-sensitive contract. Older sessions reuse paths and metadata and Docker can resume external transcripts. ## 9. Post-mortem and highest-leverage improvements

**Reconstructed failure sequence from the controls.** An operator invokes `daemon run-job`. The socket server begins job execution. Around two seconds later the client times out even though the original worker is pending. The CLI starts its fallback path against the same job configuration. The daemon’s internal map has already shown how overlapping starts can displace a label, and the separate CLI fallback creates a separate daemon object with its own map. At completion, the run-record write can cause bookkeeping to stick or two runs sharing one timestamp can overwrite the same file. No single observer owns the truth across those stages. In this review the input was an ordinary local request and the work was a deferred fixture. The consequences for a production job depend on which operations it performs and whether they are idempotent. (`src/daemon/control-socket.ts:182–204,265–267,298–356`, `src/daemon/daemon-command.ts:210–223`, `src/cron/job-commands.ts:587–598`, `src/daemon/ironcurtain-daemon.ts:475–497,561–592,614–665`, `src/cron/job-store.ts:81–87`.)

**Why this became possible.** The daemon combines independently useful mechanisms. The UDS gives the CLI location transparency, the scheduler uses a low-overhead poll plus a running-label map, and a run’s timestamp sorts its history. Those mechanisms work best when launches are single-owner and return quickly. In the workflow runtime, one state at a time made synchronous state publication, a per-bundle policy and a process logger manageable. The lazy shared-container and fan-out paths gained better startup cost and throughput at the cost of new ownership intervals. Existing comments acknowledge the single logger owner and state-boundary lane drains. Growth exposed gaps that individual passing state or transport tests could leave untouched. This explains the findings using the implementation at the pin. The shallow repository provides no merge-history evidence for authors’ intentions. (`src/cron/cron-scheduler.ts:185–234`, `src/cron/job-store.ts:81–105`, `src/logger.ts:3–20`, `src/workflow/orchestrator.ts:997–1008,1243–1257,2966–2987,3054–3075`, `docs/designs/evolve-sync-parallelism-phase0-audit.md:9–17`.)

**1. Separate acceptance from completion and give each scheduled execution an owner.** Use an explicit acknowledged `runId` and status lookup for daemon requests, end the connect timer on connect, and map a post-dispatch disconnect to an unknown result that can be reconciled by ID. A direct local launch is safe when the control-plane evidence shows the daemon never accepted the operation. The schedule and manual paths should claim the same job admission slot before the async factory, use an ownership token to clear only their own claim, and release the session and slot in `finally` even when persistence fails. Two daemons in the same state directory should resolve a live owner conflict before either begins scheduling. Use a unique run identity in the record filename. Regression gates are a delay across two and thirty seconds, two arrivals around the factory await, a record-write failure, and two same-millisecond starts. This directly targets F1–F3. (`src/daemon/control-socket.ts:141–171,182–204,298–356`, `src/daemon/ironcurtain-daemon.ts:561–604,635–665,746–765`, `src/cron/job-store.ts:81–87`.)

**2. Make cancellation joinable from admission through terminal publication.** Reserve workspace and invocation ownership before launching an asynchronous factory, attach a cancel signal or a post-resolution check to each acquisition, and use one shared teardown promise for abort, natural completion and shutdown. Thread cancellation through the actor callbacks into builtin provider requests, deterministic `execFile`, and the per-invocation runtime abstraction. Maintain separate status for stopping and fully drained. Canonicalize and claim the workspace before writes and apply the claim to both start and resume, including their cross-process entry paths. The regression gate is observable absence of new work after abort and release of exactly the owned resources after an in-flight factory, stale close callback, or second abort. This addresses F4–F7 and preserves the useful existing bundle rollback. (`src/workflow/orchestrator.ts:1010–1104,1243–1257,1557–1579,1729–1736,2057–2160,2181–2208,2515–2544,4389–4554`, `src/session/agent-session.ts:195–204,257–278,313–325`.)

**3. Define a durable checkpoint envelope.** Put format version, current recoverable state, generation and stable run ID in a validated disk record. Use explicit per-entry classification for discovery and import, preserving the ability to resume intact neighbors. Treat a failed initial save as a clear acknowledgment state, such as rejected or running without recovery, and surface failures of subsequent saves with the last known durable generation. Write new generations and event markers with an explicit publication/reconciliation rule. Keep ordinary replay and evolve recorded-lane recovery distinct at the API where they have different guarantees. Re-test with good, missing, shape-invalid, truncated and legacy records and a mid-write fault. This addresses F8 and makes an interrupted run understandable from persisted evidence. (`src/workflow/checkpoint.ts:17–19,53–75`, `src/workflow/checkpoint-selection.ts:33–56`, `src/workflow/orchestrator.ts:1642–1646,1688–1725,2353–2364,3386–3408`.)

**4. Scope logging and counting to the owner.** Inject an explicit session log sink instead of resetting the process sink from session close. Carry immutable workflow/session/turn identity at stream admission and keep delivery alive through response drain. The metrics lease design provides an existing identity model to compare against. Report attribution and coverage separately where an adapter cannot supply exact counts. Run interleavings where A finishes before B issues its next request, B’s stream attaches before A finishes, and both producers close while the daemon remains live. This addresses F10–F11. (`src/logger.ts:45–96`, `src/workflow/orchestrator.ts:1514–1521,2641–2666,2926–2958`, `src/docker/mitm-proxy.ts:1466–1469,1517–1526,2541–2543`, `src/llm-metrics/attribution-registry.ts:55–141`.)

**5. Specify calendar and test-runner semantics.** Parse whole fields and preserve which grammar is accepted. A forecast needs to return a real matching time or communicate the search bound. Decide whether restarts, reloads and missed slots intentionally coalesce or backfill work, then persist whatever claim is necessary. Add those cases to the supported-runtime tests. For the release pipeline, keep a small offline coordinator/session test tier independently runnable from locked, cached prerequisites so an unavailable model or native addon cannot erase basic orchestration evidence. This addresses F9 and the test-environment loss of coverage. (`src/cron/cron-scheduler.ts:74–170,203–255`, `vitest.config.ts:21–55`, `.github/workflows/ci.yml:38–81`.)
