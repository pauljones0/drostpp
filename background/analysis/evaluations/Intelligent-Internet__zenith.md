## 2. Core architecture and end-to-end control/data flow.

Zenith is a local harness attached to a coding-agent host. The host agent handles the user's interaction, requirement interpretation and planning. The Python process exposes MCP tools and owns the runnable frontier, task transitions, handoff application, and gate evaluation. Workers, validators, and the closing reviewer run in fresh ACP sessions. The bundled host-native subagents used for contract review and investigation belong to the host's agent runtime. Zenith owns the ACP sessions and sidecars it starts for tasks. There is no periodic runner driving the graph in the controller. The host drives it through explicit calls. `zenith/README.md:34–69`, `cli.py:82–151,366–424`, `server.py:38–66,418–464`, `controller.py:120–156`, `bundled/prompts/orchestrator/system_prompt.md:19–30,133–146`.

```text
User → host orchestrator → stdio MCP → ProjectController → MissionCoordinator
                                      │                       │
                                      │                       ├─ work / validate → ACPNodeDispatcher
                                      │                       │   ├─ loopback HTTP MCP sidecar
                                      │                       │   └─ ACP agent via line-delimited JSON-RPC
                                      │                       ├─ gate → persisted validator verdicts
                                      │                       └─ closure → ACPTerminalReviewer + report sidecar
                                      └─ ProjectStore ↔ state, graph, and reports on disk
```

1. **Bootstrap and plan.** The Click entry point installs provider assets and writes the host's MCP configuration. `start_project` creates a bucket, records the original brief, seeds project memory and skills, and points workspace discovery surfaces at the bucket. It enters `mission_planning` with a mission ID. The host writes assertion Markdown and submits `TaskList`. Submission checks task IDs, shape, referenced dependencies, cycles, and exactly one work owner per assertion, then persists the graph and initializes its cursors. `cli.py:97–151,377–424,449–485`, `controller.py:74–118`, `storage.py:164–233,664–717`, `task_validation.py:168–251`.
2. **Schedule.** A mutation normally acquires a project-local lock on one MCP server and runs in `asyncio.to_thread`. The controller loops `step()` until a terminal, idle, or attention result, or a counted step exhausts the caller's budget. Each mission step reloads disk, reconciles marked-running tasks first, evaluates one ready gate next, then selects ready tasks in list order. A fully ready group of direct validator predecessors gets priority. The ordinary path selects up to the configured cap. The two worker path shapes write `running` and the attempt timestamp before dispatch. Batch outcome application waits for the full group and then proceeds by task ID. `server.py:102–119,186–199`, `controller.py:120–138`, `coordinator.py:92–176,190–305`.
3. **Run a lane and return evidence.** The runner resolves the role's provider and command, picks a loopback port, starts the role-specific MCP child, renders the first message, and starts the ACP adapter in the project workspace. The client sends `initialize`, `session/new` with the MCP URL, optionally `session/set_mode`, then `session/prompt`. Inbound ACP handlers serve messages, permission requests, files and terminals. The sidecar exposes only `end_node` to a worker or validator and only `submit_terminal_review` to the closing reviewer. It takes the output route from its launch environment. It writes a typed JSON result through temporary-file replacement. After the prompt responds, the runner polls for up to two seconds, performs cleanup, and reads the result. The coordinator records the JSON and a Markdown mirror and applies it to task, contract and attention state. `acp_runner.py:342–489,638–815,817–959,966–1074`, `server.py:69–94,290–395`, `storage.py:406–484`.
4. **Verify and replan.** Successful work clears its dependencies. Failed work stops for a decision. Validation tasks record completion separately from the substantive verdict and become cleared so downstream gates can evaluate their evidence. A gate walks transitive validator predecessors and combines per-target verdicts conjunctively. A missing expected item is failing evidence. A passed gate also raises a checkpoint. Failed and checkpoint gates, node reports, and terminal gaps use the same attention interface. A decision may continue, retry a failed node, patch the graph, stop, or plan a follow-up mission after a terminal review. `coordinator.py:368–419,460–712,745–752`, `controller.py:158–182,206–364`.
5. **Close.** The host explicitly calls `end_mission`. The coordinator checks for runnable work and ready gates, reconciles marked-running tasks, then invokes the closing reviewer on the initial brief and workspace. A positive verdict writes closeout and `Done`. Gaps reopen attention. `next_mission` records an acknowledged-gap closeout and increments the mission sequence. The review prompt asks the reviewer to independently inspect the product and avoid prior reports. The same workspace and ACP capabilities remain available to that role. `controller.py:140–156,324–336`, `coordinator.py:427–454,718–739`, `acp_runner.py:1105–1120`, `bundled/prompts/terminal-reviewer/system_prompt.md:3–16,68–88`.

Three kinds of state cross these boundaries. The project bucket's `.zenith/` contains human and agent material such as brief, guidance, memory, skills, contracts, numbered decisions, attempt mirrors and closeouts. `.zenith-runtime/` contains machine cursors and raw JSON handoffs. The actual implementation and experiment files live in the workspace, where all destinations share the same files unless the caller supplies a custom dispatcher or explicit working directory. File placement helps readers distinguish record from cursor. Local identities share the files, and related records commit separately. `config.py:235–253`, `storage.py:1–14,139–158,398–444,538–656`, `dispatcher.py:19–39`, `acp_runner.py:670–680,1247–1278`.

## 3. Why the design works and its governing invariants.

| Invariant or rationale | Enforcement and boundary |
| --- | --- |
| One owner for each acceptance assertion | Coverage uses the task graph and the active work-owner set. Targetless work supports setup, discovery and integration. Runtime checks file names and graph structure. The prose criterion, evidence floor, disjoint file scopes and validator placement depend on authoring and review. `task_validation.py:37–71,92–118,168–251`, `bundled/prompts/orchestrator/system_prompt.md:214–263`. |
| Ready work has cleared dependencies | The engine checks **cleared** for every declared predecessor. The design removes or rewrites retired dependencies at patch time to keep runtime scheduling simple. Cleared and running tasks are protected from retirement, as are cleared-gate ancestor subgraphs. Acyclicity and coverage are rechecked on the rewritten plan. Patch chaining can break the assumed absence of retired edges, as S08/E03 show. `coordinator.py:190–211`, `task_list_patch.py:33–85,139–255`. |
| Scheduling outcome is interpretable | List order breaks ordinary readiness ties. A ready gate is visited in gate-ID order. Gathered batch effects are applied in task-ID order, so completion timing does not choose the attention ordering. Choosing an entire validator lane can delay unrelated work until that evidence is available. `coordinator.py:129–146,190–305,460–473`. |
| Evidence is layered | Worker completion opens validation. Per-target validator verdicts govern deterministic gates. Gate checkpoints let the host reassess scope before a dependent wave. The closing reviewer sees the original brief, which can expose a material gap absent from the plan. A reviewer verdict remains an agent claim. The project may be stopped or advanced on recorded operator judgment. `coordinator.py:368–408,475–587,677–739`, `controller.py:275–336`. |
| Critical choices are inspectable | A normal attention response returns IDs and reports. Each open ID needs exactly one decision. Audit Markdown records the justification and patch, and the envelope can return a compact frontier or a full task list. Runtime status, queue, audit, and presentation are separate files and views. Ordering and cross-file consistency therefore depend on the controller's mutation discipline. `controller.py:158–182,206–273,370–394`, `envelope.py:30–61,342–367`, `storage.py:515–593`. |
| Role separation narrows the RPC surface | The role-specific tool registry and per-process environment constrain which report the expected client can submit through MCP. A sidecar knows the assigned task ID without asking the agent to supply it. ACP delegates execution authority through the common local workspace, process environment and permissions. Prompt rules and provider cooperation supply the remaining separation. `server.py:38–94,301–395`, `acp_runner.py:154–219,455–537,966–1038`. |

This design keeps semantic decisions in the host and deterministically enforces the edges it can represent. Independent agent context addresses the tendency to trust an implementation agent's own evidence. A small local state kernel and plain artifacts make ordinary runs easy to explain and resume when the current attempt has one intact result and no active conflicting owner. S01 and T01 exercised the normal checkpoint and explicit-close boundaries. `technical_report/from_ralph_to_zenith_brand.tex:371–395,633–639`, `coordinator.py:92–146,718–802`.

## 4. What it does well and poorly, with source evidence.

**Strengths.** The public surface is small and the project states are finite. Graph validation is separated from execution, so normal scheduling rules can be tested without a provider. Concrete dispatcher and reviewer protocols provide useful seams. Task-level validation, gate-level consensus, and original-brief review each catch a different class of error. Project-local text artifacts make changing intent and the evidence supporting it inspectable. Error synthesis turns an ordinary child failure into a decision point and captures stop reason, exit code and a bounded excerpt of stderr for worker failures. S01, S03, T01 and T03 exercised these strengths. `models.py:225–299`, `task_validation.py:218–251`, `dispatcher.py:19–39`, `coordinator.py:368–419,475–587,718–739`, `acp_runner.py:1195–1217`.

### Scheduling, graphs and evidence

- **Admission is gated by dependency order and batch boundaries.** Validator-first lanes can deliberately exceed `max_parallel_nodes` before the ordinary cap is consulted. The repository explicitly tests parallel validators in serial mode. There is also no shared cap across project locks. Completed siblings cannot unlock their dependents until the whole batch returns. This is a simple deterministic scheduling policy with a misleading overall-cap name and slow-tail behavior. S02, S03, C04, P02 and P03 separated these effects. F01 repeated the cap result with six simultaneous real ACP transports and isolated one validator failure from its peers. `config.py:15,36–43,123–125`, `coordinator.py:129–146,214–349`, `controller.py:129–136`, `tests/test_coordinator_parallel.py:132–224`.
- **Graph patches can violate the graph contract.** A same-patch chain or a mapping to an already retired replacement can leave live edges pointing at superseded tasks. The patch code rewrites once and rechecks only structural reachability and work coverage. Separately, shallow copying shares `TaskStateEntry` instances and can mutate the caller's original state on a rejected pure patch. The frontier hides retired edges and may show the stuck dependent as ready. Closure checks for runnable work. Pending non-runnable tasks can remain. S08/E03 exercised the deadlock and acknowledged close with an injected clean reviewer. `task_list_patch.py:57–85,153–218`, `models.py:355–386`, `coordinator.py:190–211,427–454`, `envelope.py:139–169,311–321`.
- **Evidence indexing diverges from evidence authorship.** An eligible validator's extra item can dissent on a different validator's assigned target. Duplicate rows use the last value in a gate. An incomplete handoff with a positive row can clear the gate, and the contract cursor remembers positive claims even when the gate fails. An unknown item ID can become a cursor entry and make a subsequent patch require a work owner for a nonexistent contract assertion. The aggregation source and cursor update need a common scope boundary. V01/E02/E04 exercise these combinations. `coordinator.py:388–408,475–544,614–642`, `controller.py:338–364`, `server.py:337–354`, `models.py:321–338`.
- **Contracts remain mutable across the validation boundary.** Submission indexes the filename pattern, which can accept an empty file, directory or dangling symlink. Rendering reads assertion bodies, even for the worker template that only emits paths. Editing the existing file under the same ID after validation leaves the earlier verdict applicable to the gate. The host's prompts instruct authors to revalidate changed criteria, so this is a versioning boundary for the runtime. V02, T07 and E02 show the distinct cases. `task_validation.py:37–71`, `storage.py:334–353`, `acp_runner.py:1080–1103,1132–1166`, `bundled/prompts/worker/template.md:15–19`, `bundled/prompts/validator/template.md:18–26`, `bundled/prompts/orchestrator/system_prompt.md:309–317`.

### Extension and workspace boundaries

- **Extension results are weakly bound to their request.** The dispatcher API returns an ordered list. The coordinator checks list length and pairs by position, with no result-ID equality check. The file parser selects expected type by task kind, but a payload's `node_id` need only be a string. V04's reversed fake batch cleared both tasks under the wrong report IDs. Built-in `asyncio.gather` yields request order, and the ordinary MCP sidecar sets the assigned ID, which explain the healthy built-in control. `dispatcher.py:19–39`, `coordinator.py:307–349,368–408`, `acp_runner.py:1173–1178,1265–1292`, `server.py:329–354`.
- **The write/result channel is cooperative.** The host exposes disjoint MCP tools and the runner binds sidecars to loopback, yet a bare TCP connect is the readiness check and the assigned sidecar URL has empty headers. A second submission replaces the first in both role tools. The ACP process inherits the environment and can use the workspace and terminal callbacks. Co-located workers rely on the plan author to order shared writes and fixtures. The code includes an explicit autonomy policy for provider permissions. The stdio bootstrap allowlist can also persist designated authentication environment values in the generated provider config. These are local trust assumptions and launch/transport contracts. T02, T09 and I03 verify specific mechanics. `acp_runner.py:94–219,455–537,633–636,682–708,1040–1059`, `server.py:290–395`, `cli.py:22–42,339–344,377–424`, `bundled/prompts/orchestrator/system_prompt.md:255–263`.
- **Bootstrap and project scopes can collide.** A project ID repeats for equal first-line slugs in one second. The second creation can retain the first brief and runtime history while replacing the workspace pointer and state. With distinct IDs sharing a workspace, existing live skill and `AGENTS.md` links can still point to the first project. In addition, the Codex TOML marker excludes root defaults and the features table, which a second init appends again. A checkout-based bootstrap is required by the installed `zenith init` implementation. V03/V05 and the packaging control tested these boundaries. D02 also showed that a workspace file gets as far as staging a bucket before the shim operation rejects it. `storage.py:164–233,664–717`, `cli.py:347–374,399–446`, `zenith/README.md:15–19,34–43`.

## 8. Post-mortem: design pressures, accumulated tradeoffs, likely failure modes, and the highest-leverage improvements.

The bundled technical report describes a progression from repeated gap-finding to independent milestones and an orchestrator that can revise the plan, verifier roles and reusable skills. The code implements that separation at a useful level for an interactive coding host. The testable plan kernel and readable artifacts are worth preserving. The same priorities explain the persistent decision trail, strict work coverage, explicit gate checkpoints, separate terminal review and shared workspace. This evaluation did not replicate the benchmark. `technical_report/from_ralph_to_zenith_brand.tex:371–395,631–652`, `bundled/prompts/orchestrator/system_prompt.md:3–30,211–263`.

The runtime assumes every project has one healthy supervisor, and every active call runs to a single orderly commit. That assumption holds while one host drives the server serially, a child returns promptly, and files are coherent. Once the transport times out or the supervisor dies, a job that is still running and a job that is genuinely interrupted have the same disk representation. A stale file is then an apparently useful recovery value. The live writer has the same path as the replacement supervisor, so the second supervisor cannot fence off a late artifact. Missing attempt ownership explains both the wire-cancel and SIGKILL results. `server.py:186–199,276–282`, `coordinator.py:148–176,758–802`, `acp_runner.py:682–815`, `storage.py:406–484`.

Plain files are well suited to the human record. They are also responsible for coordinating pairs of machine writes such as queue and public state, JSON and Markdown, and plan and task cursor. A process failure in one gap preserves plausible but contradictory artifacts, and an interrupted or malformed attempt can preempt every later step. Work acceptance and closure are affected because the same state derives scheduling, evidence and allowed decisions. The most efficient improvement is a single durable transition boundary and a fenced attempt identity, with the current Markdown rendered from committed state. `controller.py:158–182,338–364`, `coordinator.py:427–454,718–802`, `storage.py:64–75,431–456,515–637`.

Layering helps detect bad model claims only if the implementation preserves exactly which role produced which evidence and for which revision. The cursor currently mixes observed and accepted assertions, the patch rewrites reachable edges with no retired-edge check, and the close path equates quiescence with permission to ask for a review. At scale, an oversized validation lane or one silent child delays the whole batch, while a separate project can keep launching work. Those are different failure modes from inaccurate model output. They can be exercised entirely with local controls. `coordinator.py:133–146,214–349,388–408,427–544`, `task_list_patch.py:153–218`, `models.py:328–347`.

For long-running use, prioritize cancellation fencing and fail-closed closure, then restore attempt provenance and consistent graph/evidence validation. After these boundaries are established, asynchronous ownership and timestamped events can remove much of the operational ambiguity without changing how the host authors plans or how people read reports. `controller.py:120–182`, `server.py:434–455`, `coordinator.py:718–802`.

## 10. Prioritized improvements.

1. **P0 · Fence active work and make abort terminal.** Pick a single owner per project across MCP servers and CLI. Give each attempt a lease or supervisor generation, explicit identity, and a cancellation signal shared across the async/thread boundary. Prevent stale handoffs from updating an aborted generation. Apply deadline policy to handshake, prompt, and tool wait separately. Own the adapter, sidecar, and launched terminal groups from their first successful spawn and clean them in independent, bounded exit paths. Regression tests should interrupt before readiness, during prompt, after raw handoff, and during server death. The acceptance test is that no stale owner can mutate the cursor or overwrite committed evidence. C01, T05–T09, I02, M02, X01.
2. **P0 · Fail closed at the closing review boundary.** Remove the always-clean production fallback. Validate runner config before serving mutation tools, and surface a structured unavailable-review result with its cause. Persist a closing-attempt state and accept one matching verdict for the current generation. Distinguish complete, blocked, failed, and acknowledged-gap states. Guard closure against unresolved attention and blocked active tasks. Test invalid launch config and each part of the closeout transition. M01, C02, S08.
3. **P0 · Make attempt and state transitions recoverable.** Use stable unique IDs independent of the display clock. Bind handoffs to project, mission, task, and generation and make the accepted payload write-once. Reconcile the exact current ID and represent stale, malformed, and missing outcomes explicitly. Validate an entire decision batch on a working copy and commit state, queue and audit together. A small transactional store or versioned journal can publish current JSON/Markdown views after commit. Retain old artifact paths for audit and make mirror rebuild idempotent. S04–S07, C02/C03, T02/T04, E01.
4. **P1 · Validate graph and evidence semantics at their boundaries.** Make retirement either resolve chains once and reject loops or disallow chains in one operation. Reject live edges to retired tasks and apply one authoritative readiness function to both scheduler and envelope. Verify validator role, exact target set, uniqueness, completion, and coherent aggregate. Keep observed rows separate from accepted assertion state and version assertion contents. Defer unsupported placements or overrides to an explicit, audited decision. Seed tests with unknown, duplicate, incomplete, stale and reversed payloads. S08, V01/V02/V04, E02–E04, D03/D04.
5. **P1 · Bound resources and make job status useful to the operator.** Give worker and validator lanes explicit capacities under a total ceiling and separate workspace resource constraints. Receive results independently of the slowest sibling and persist when each accepted job is settled. Add typed timestamps, lifecycle stages, correlation IDs, return codes and structured failure taxonomy, with a bounded event buffer. Advance can retain a blocking convenience path over a durable job API, while inspect returns a coherent snapshot. Require a protocol-level sidecar readiness handshake and bound diagnostic buffers. S03, C04, P01–P03, T09, I01.
6. **P2 · Narrow and test extension contracts.** Consolidate provider selection and worker/reviewer launch glue. Use argv-aware terminal launch, explicit local trust settings, scoped environment forwarding and an intentional skill discovery contract. Make generated TOML structurally idempotent, and choose whether a wheel-only init is supported. Update stale source/spec references, replace the false-green test fixture, and make local real-wire no-credential tests and crash fences part of CI. Version and test the dependency range as well as its lockfile. V03/V05, D01, I03, M03.
