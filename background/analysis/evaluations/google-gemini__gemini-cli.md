**Assessment.** Gemini CLI has a capable shared scheduler, a provider boundary that supports realistic offline tests, and a transcript format designed for interrupted tool rounds. Its weakest point is ownership across caller loops. A response stream can discard an attempt in chat history while callers still execute that attempt's tool requests. Reusing one prompt ID across multiple user messages makes cancellation roll back earlier successful dialogue. In the SDK, a separate resume converter can lose the model half of a saved tool exchange. The highest-leverage change is to give one runtime owner each user prompt and its tool continuations, with explicit attempt commit, one terminal outcome, and a shared resume codec.

## 2. Core architecture and end-to-end control/data flow

The sequence model keeps tool continuations coherent when caller-supplied prompt identity has the right lifetime. The client checks a session-wide counter at model-turn entry and carries a separate recursion allowance for next-speaker and loop recovery. Host loops can impose their own turn limits. `Turn` gathers provisional tool requests, translates thoughts/text/citations/usage, and reconciles its own state when a stream retries. ### Tool scheduling, authority, and side effects

`Turn` normalizes provider function calls into requests keyed by call ID, tool name, and prompt ID. The scheduler resolves the name against the scoped registry, builds a validated invocation, and converts unknown tools and bad inputs into correlated terminal results. One batch owns the active map while later calls queue. Topic changes sort first. Adjacent parallelizable calls enter a wave, with validation and approvals completed before execution. Edit tools and explicit `wait_for_previous` requests delimit waves. This makes waves an ordering convention. Toolkit or extension authors still own resource safety inside parallel invocations. [Turn identifiers](repos/google-gemini__gemini-cli/packages/core/src/core/turn.ts:473), [batch ingress](repos/google-gemini__gemini-cli/packages/core/src/scheduler/scheduler.ts:345), [invocation build](repos/google-gemini__gemini-cli/packages/core/src/scheduler/scheduler.ts:421), [wave lifecycle](repos/google-gemini__gemini-cli/packages/core/src/scheduler/scheduler.ts:476), [parallelization rule](repos/google-gemini__gemini-cli/packages/core/src/utils/tool-utils.ts:25).

A tool decision combines the invocation's effective arguments, optional BeforeTool rewrite, approval mode, policy rules, and invocation-specific confirmation details. The scheduler uses policy results to deny, allow, or resolve a confirmation, with context and arguments available to the policy engine. Confirmation subscribes by correlation ID before publishing the request and accepts a scoped outcome or abort. The message bus can derive a subagent view of the parent policy/transport. Runtime policy sits beside lower-level execution and sandbox services, which handle concrete file/process operations. Built-ins and MCP tools meet the same scheduler contract. Ordinary terminal results use `functionResponse` keyed to the original call ID and name. A tail call replaces the active invocation and re-enters validation under that original external identity. ### Streaming, persistence, and continuation

`GeminiChat` prepares a request, opens the provider stream under connection retry, then pulls chunks under a separate mid-stream retry and validation boundary. It streams provisional chunks and buffers transcript thoughts, usage and model parts until the attempt passes validation. After the retry marker, `Turn` resets its candidate state. The host still has to honor that boundary as it buffers requests and text. The chat records the user message, then the accepted model message and scheduled tool calls. A cooperating host records terminal tool outcomes, and a subsequent chat request appends durable function responses. `LegacyAgentProtocol` translates the raw stream to stable event IDs and a bounded runtime interval between `agent_start` and `agent_end`. The wrapper can replay retained in-memory events by event or stream ID and subscribes before reading the event history so live delivery can overlap attachment. Consumer detachment unsubscribes the reader. Aborting the background work is a separate protocol operation. [Chat send and retries](repos/google-gemini__gemini-cli/packages/core/src/core/geminiChat.ts:546), [mid-stream retries](repos/google-gemini__gemini-cli/packages/core/src/core/geminiChat.ts:717), [successful stream persistence](repos/google-gemini__gemini-cli/packages/core/src/core/geminiChat.ts:1883), [recording terminal tool outcomes](repos/google-gemini__gemini-cli/packages/core/src/core/geminiChat.ts:1965), [legacy session loop](repos/google-gemini__gemini-cli/packages/core/src/agent/legacy-agent-session.ts:174), [stream replay](repos/google-gemini__gemini-cli/packages/core/src/agent/agent-session.ts:64).

## 4. Strengths

1. **Provider seam with high-fidelity testing.** File-backed playback runs the real history, routing, turn, and tool layers. A loopback gateway can also exercise the installed Gemini SDK's HTTP and SSE parser without live credentials. In the review, the latter allowed a valid tool chunk and a retryable error to occur in the same real stream. This seam is more useful for runtime regression tests than mocks at each layer independently. [Content generator](repos/google-gemini__gemini-cli/packages/core/src/core/contentGenerator.ts:210), [playback](repos/google-gemini__gemini-cli/packages/core/src/core/fakeContentGenerator.ts:70), [gateway](repos/google-gemini__gemini-cli/packages/core/src/core/contentGenerator.ts:344).
2. **Tool work is explicit, typed, and recoverable.** The scheduler separates request admission, validation, confirmation, execution, state projection, and finalization.
