## 2. Core architecture and end-to-end control/data flow

### Composition and ownership

A city is a directory and a configuration boundary. Rigs contribute repository scope and namespace. TOML composition resolves includes and imports, captures provenance and fingerprints convention trees before reading them so an edit during composition cannot give the older content a newer revision. The configured provider describes the agent program, arguments, launch and prompt behavior. The session runtime transports, observes and controls the program. A pack can provide agents, prompts, formulas, mechanical commands, orders and provider-specific hook overlays. The bundled registry embeds core, bd and Dolt content and imports the public Gas Town and Gas City planning packs through a pinned Go module. The Go `internal/` layout makes “SDK” primarily a composition and CLI/API proposition at this snapshot. ### Orders, conversation operations and wake queues

The paced orders lane resolves scoped orders, checks suspension/backend, tracking and real open work, then evaluates cooldown/cron, condition or event triggers. Condition probes run with a deadline and bounded parallelism. Successful condition signals get dispatch priority beyond the usual per-tick rotating budget. A tracking bead is created before async work. An order invokes a formula or a script. Exec operations have timeouts, process cleanup, and records for result or failure. Event triggers keep a durable last-run cursor and memory-only floors, with fresh orders beginning at the local observed head. ## 4. What it does well and poorly, with source evidence

**Durable workflow mechanics with meaningful failure classes.** The graph uses typed outcomes and topology, allows resuming already-initialized fragments, and makes root cancel/terminal state visible before more retry work is minted. The dispatcher distinguishes ordinary pending, infrastructure unavailable, semantic refusal and scope drift. Unavailability can retry without billing the ledger it cannot reach. Semantic failures accrue a durable budget and can settle/quarantine. An externally repairable drift stays open and gets surfaced. A one-shot notification can still be lost after its durable state is recorded. [Fan-out recovery](repos/gastownhall__gascity/internal/dispatch/fanout.go:350) · [Terminal controls](repos/gastownhall__gascity/internal/dispatch/runtime.go:314) · [Tier dispositions and event gap](repos/gastownhall__gascity/cmd/gc/cmd_convoy_dispatch.go:480)

**Separation of slow observation and guarded effects, with holes in cancellation and accounting.** Per-source single flight keeps a blocked backend from piling an identical read up each pass. The newer worker observer does the same by session key and starts nothing for an expired context. The v2 fence helper independently launches goroutines on every call, and returns at its deadline without joining a context-blind operation. The effect executor releases an inflight slot at ambiguous settlement while retaining the underlying Run in a different registry. A name lock can preserve correctness while a hung operation consumes resources. The planner join itself waits on `p.done` without selecting on the shutdown deadline. Focused extracted controls show the latter two primitives' behavior under a blocked pass or repeated canceled probes. Their deployment frequency was not measured. [Per-source flight](repos/gastownhall__gascity/cmd/gc/allocator_backstop_lane.go:616) · [Keyed worker observation](repos/gastownhall__gascity/internal/worker/observe_bounded.go:48) · [Fence probe helper](repos/gastownhall__gascity/cmd/gc/reconcile_session_fence.go:346) · [Effect abandonment](repos/gastownhall__gascity/cmd/gc/reconcile_session_effects.go:256) · [Planner join](repos/gastownhall__gascity/cmd/gc/reconcile_planner.go:555)

**Runtime ownership is strongest through the governed entry points.** Subprocess uses process groups, drains descendants when a leader has exited, preserves identity metadata ahead of socket publication, and retries cleanup with explicit uncertain-death results. The local transport still has a demonstrated split between process ownership and discoverability when two provider objects share one directory and race a same-name start. Each object's mutex protects only itself. The code checks the socket before spawn and unlinks it at publication, so a later publisher can shadow an alive process. ## 8. Post-mortem: design pressures, accumulated tradeoffs, likely failure modes, and the highest-leverage improvements

**The checked-in route incident.** The route order had treated the event's payload as one wire shape. Cache-generated bead events and the typed API path published two representations, so a structurally valid route could be invisible to this one consumer. HEAD fixes both shapes and tests both. The remaining defect comes from three different delivery boundaries. The order makes the event cursor durable before the shell runs. The shell starts another query against a finite time window. Its batch processor silently replaces partial output with empty on a final-row error, and its side-effect receipt has only bead and target identity. A skip anywhere in that chain can look like a clean run. A later scan can recover some cases before the lookback expires. A durable claimable bead also gives the allocator or a polling agent a route to progress when the delivery was only a wake. The separate route recovery lane restores eligible missing canonical routes and reports coverage gaps. That fixes route metadata. It does not prove the already-routed seat received input. First-order impact is unknown extra wake latency and missing evidence in the order's outcome. In a deployment relying on that wake for an existing parked seat, work can remain unobserved until another mechanism exercises the route. The checked-in release gate identifies the malformed-tail limitation, says the tested deployment had the order disabled, and reports upstream remote test counts. Those counts and deployment statements are source evidence only. The loop failure and receipt limitations are independently reproduced here. [Route fix and selector](repos/gastownhall__gascity/internal/bootstrap/packs/core/assets/scripts/nudge-on-route.sh:97) · [Store cursor before execution](repos/gastownhall__gascity/cmd/gc/order_dispatch.go:2189) · [Metadata recovery](repos/gastownhall__gascity/cmd/gc/route_recovery.go:175) · [Pinned release gate](repos/gastownhall__gascity/release-gates/ga-2grxd34s-nudge-on-route-shapes-gate.md:37)

**Backpressure can erase a decision when the budget is placed too late.** Order dispatch records a historical case of a roughly 40-order city with a permanently full budget to which a short-lived condition signal was subject. The reported 11 hours without a merge-queue dispatch came with neither gate error nor suppression. Current code moves positively evaluated conditions ahead of ordinary sweep allocation and reports a sample of unreached budgeted candidates. That preserves signals already observed, while many simultaneously due conditions can still produce a burst of durable launches. The analogous v2 tradeoff is a globally sequenced pass that evaluates a coherent city snapshot but coalesces dirty-key work under one broad cycle. Slow sources contribute staleness or delay, and total work grows with the sources and candidate seats visited. The important operational distinction is whether a signal was due and deferred, never checked, unobservable, or admitted and failed. Those states need different remedies and measurements. [Historical order starvation and correction](repos/gastownhall__gascity/cmd/gc/order_dispatch.go:824) · [Budget trace](repos/gastownhall__gascity/cmd/gc/order_dispatch.go:885) · [V2 scheduling](repos/gastownhall__gascity/cmd/gc/reconcile_planner.go:323) · [Demand freshness](repos/gastownhall__gascity/cmd/gc/reconcile_gather.go:206)

**Terminal state has to be enforced where new effects begin.** Dispatch source records a historical failure where a root was closed before a contested subtree sweep, and a child kept retrying for almost five more hours. That number is a checked-in account. The durable root outcome had been correct, while its authority had stopped at the finalizer. The root gate now runs before each control mutation so descendants can converge incrementally, with explicit teardown exceptions. Quarantine closes before emitting a stall event and can lose that event on a process death. A durable error remains inspectable, so alerting on the persistent state closes a different failure class from event replay. The lesson also applies to across-ledger writes. **Ownership defaults have outgrown one process.** Default transports, embedded stores and single-city locks simplify local deployment.
