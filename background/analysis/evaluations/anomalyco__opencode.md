## 2. Core architecture and end-to-end control/data flow

### Host, service graph and admission

The protocol defines the HTTP representation of session operations. The server translates decoded requests and domain errors, leaving orchestration in Core. The embedded SDK starts the same route graph in a ManagedRuntime, adapts it through an owned fetch transport, and exposes selected direct session operations. The SDK scopes the host to its caller and stops the recovery fiber with it. Operational stores, the event bus, jobs, and session execution are shared within the host. Its instance selector obtains scoped capabilities for a session's current Location. The default selector canonicalizes directory and workspace and borrows the corresponding LayerMap entry. An embedded host can add a private sharing key and recreate its plugin configuration on a miss, including after restart. [Prompt protocol](repos/anomalyco__opencode/packages/protocol/src/groups/session.ts:342), [server handler](repos/anomalyco__opencode/packages/server/src/handlers/session.ts:290), [server composition](repos/anomalyco__opencode/packages/server/src/routes.ts:132), [SDK assembly](repos/anomalyco__opencode/packages/sdk/src/effect/opencode.ts:36), [embedded host and recovery](repos/anomalyco__opencode/packages/sdk/src/internal/host.ts:30), [Location selector](repos/anomalyco__opencode/packages/core/src/location-services.ts:72), [private SDK instances](repos/anomalyco__opencode/packages/sdk/src/internal/instances.ts:48).

A prompt carries an ID that the caller can supply for retries. A repeated Session ID adopts the existing Session. Prompt admission looks for an existing pending item or a matching delivered message before preparing attachments, skill and agent references, and prompt hooks. Preparation is interruptible. The commit region shields the eventual admissible payload from request cancellation. The `session.inbox.enqueued` projection stores the item with a monotonically ordered aggregate sequence, and externalizes media references as appropriate. The API returns the admitted item. Its default wake is advisory, with `resume: false` available to record input without a wake. The runner separately delivers it with `session.inbox.delivered`. That event's transaction consumes the inbox row and creates the visible prompt using the stored payload. A retry after delivery looks at the projected message. [Session creation](repos/anomalyco__opencode/packages/core/src/session.ts:291), [prompt admission](repos/anomalyco__opencode/packages/core/src/session/session.ts:149), [prompt preparation](repos/anomalyco__opencode/packages/core/src/session/prompt.ts:1), [inbox reconcile and insert](repos/anomalyco__opencode/packages/core/src/session/inbox.ts:125), [blob and inbox projection](repos/anomalyco__opencode/packages/core/src/session/inbox.ts:299), [visible message projection](repos/anomalyco__opencode/packages/core/src/session/projector.ts:1008).

### Execution, scheduling and step boundaries

`SessionExecution` is process-global and keyed by Session ID. A local coordinator owns a fiber and Deferred settlement per busy period. An explicit resume joins an existing live period. A wake during a drain records a coalesced request to run again. The final check for a late wake occurs before releasing ownership, and a wake that survives settlement creates a successor. Other sessions schedule independently. Explicit interruption clears wakes belonging to the interrupted intent and returns when accepted. Wakes admitted during cleanup can start a successor. Callers that require completed cleanup use `awaitIdle`. The start hook commits the execution claim and start event together. A drain reads the current Session and borrows its Location-specific runner through Instance. A move or reload hands off at a boundary and carries the step allowance in the continuation when needed. [Coordinator ownership and wake contract](repos/anomalyco__opencode/packages/core/src/session/run-coordinator.ts:31), [run/start/settle](repos/anomalyco__opencode/packages/core/src/session/run-coordinator.ts:73), [interrupt and wait](repos/anomalyco__opencode/packages/core/src/session/run-coordinator.ts:123), [execution claim and instance dispatch](repos/anomalyco__opencode/packages/core/src/session/execution.ts:78), [completion and interruption](repos/anomalyco__opencode/packages/core/src/session/execution.ts:138).

A drain first establishes readiness and repairs interrupted tool calls and compactions from a prior owner. Before each next model step it considers inbox controls. Steered compaction can take precedence over earlier steers up to an earlier move. Delivery of a move is grouped with the placement event. The idle boundary consumes one queued input before reconsidering continuation. Running continuations observe steers at safe boundaries. New promoted input resets the configured agent step counter. The runner prepares instruction state, promotes the eligible input and reloads context. It calls `runStep` and decides whether to advance, return idle, cross a Location boundary, recover context overflow, retry, or make a tool-disabled final model call. At the first visible input an untitled root can generate a title in a Location-owned FiberMap. The experimental idle hook can admit another item at a genuine idle boundary. [Drain admission and controls](repos/anomalyco__opencode/packages/core/src/session/runner/llm.ts:63), [idle and repeated steps](repos/anomalyco__opencode/packages/core/src/session/runner/llm.ts:177), [logical step and max steps](repos/anomalyco__opencode/packages/core/src/session/runner/llm.ts:236), [inbox ordering](repos/anomalyco__opencode/packages/core/src/session/inbox.ts:561), [stale work repair](repos/anomalyco__opencode/packages/core/src/session/runner/llm.ts:389).

### Agent, model, provider request and context

Context preparation selects the current agent and model, flushes MCP discovery, takes a tool snapshot for effective agent and session rules, and gathers built-in, discovered, MCP, skill, reference and explicit instruction entries. Instruction state stores content-hashed values. The opening instruction prefix remains stable within an epoch, with durable chronological updates for changed or removed sources. An unavailable initial instruction source blocks the first execution before prompt delivery. A later temporary source failure preserves the last observation. Compaction advances the epoch so old instruction changes can be retired. [Agent and context selection](repos/anomalyco__opencode/packages/core/src/session/context.ts:147), [context load](repos/anomalyco__opencode/packages/core/src/session/context.ts:202), [blocked baseline gate](repos/anomalyco__opencode/packages/core/src/session/runner/llm.ts:227), [instruction observation and apply](repos/anomalyco__opencode/packages/core/src/session/instruction-state.ts:21), [instruction epochs](repos/anomalyco__opencode/packages/core/src/session/instruction-state.ts:126).

Selection prefers an explicit available session model, then the agent preference, then a resolver fallback. An explicitly unavailable selection fails with a typed error. Resolution applies catalog and provider configuration, variants, credential and environment bindings, and provider package routing. A model-resolve hook can select a replacement within the same provider, including an entry hidden from the picker. First-party routes use the canonical `@opencode/ai` model and event schema. A compatibility bridge loads AI SDK model factories for supported package definitions. Source configuration and model identity stay visible for accounting. The AI layer compiles the request and owns protocol encoding, transport, parsing and normalized errors. Its separate reusable `loop` supports consumers outside the Core session runner. Core calls `LLMClient.stream` explicitly and controls tool continuations through durable history. [Selection and hook](repos/anomalyco__opencode/packages/core/src/session/runner/model.ts:88), [resolver dispatch and compatibility](repos/anomalyco__opencode/packages/core/src/model-resolver.ts:201), [provider package and environment binding](repos/anomalyco__opencode/packages/core/src/model-resolver.ts:294), [catalog/credential resolution](repos/anomalyco__opencode/packages/core/src/model-resolver.ts:476), [AI Effect calls](repos/anomalyco__opencode/packages/ai/src/llm.ts:84), [request compiler and stream](repos/anomalyco__opencode/packages/ai/src/route/client.ts:570).

History is read by sequence, joining normalized message parts and hydrating blobs. Completed local summaries start a new window and can reference a verbatim recent span by message ID. A model-native window is replayable by its producing model and must decode. Other models re-expand earlier surviving messages. Lowering retains parsed tool-call/result pairs and keeps provider-native reasoning or tool metadata only within its supported identity scope. Failed partial output is pruned around tool calls that actually ran, with special continuity handling for interruptions and malformed input. Hooks receive cloned tool definitions, model-facing messages and stored metadata. The request boundary maps renamed tools back to their captured executors, strips private message metadata, translates unsupported modalities to explanatory placeholders, and clips historical image bytes using trigger and target thresholds to keep prefixes cacheable. Provider request, HTTP and WebSocket hooks have separate responsibilities. Compaction is a control flow with its own result and usage. Automatic compaction uses a catalog window and reserved capacity, a measured provider anchor when available, and a heuristic estimate for the remaining suffix. Manual compaction is promoted as durable control work. A provider overflow before visible output can trigger one recovery cycle for the logical step. The local summarizer has a separate optional model, templates, an ordered retention strategy and smaller retries. A background summary can reuse a recently warmed prefix, then swap in only if its boundary and tail remain suitable. Only successful compaction changes the effective history boundary. The project tracks the cost of summary attempts independently of when the checkpoint is adopted. ### Streaming attempts, tool calls and policy

One attempt consumes normalized AI events through the transport. Text, reasoning, tool input and tool outputs correlate by stable message, call and ordinal IDs. The first receiver starts the assistant record with the starting snapshot, acquired concurrently with the provider request. Local tool fibers start after the associated durable `Tool.Called` publication. Provider-hosted calls use the provider result and never start a duplicate local tool. The runner drains through provider completion, records `Step.Streamed`, joins local tools, settles leftover fragments and calls, records usage and finish, then releases the next step. Text and reasoning deltas are ephemeral and batched, while completed blocks and tool settlements are durable. Provider and tool fibers keep per-source order without a shared writer queue. [Attempt lifecycle](repos/anomalyco__opencode/packages/core/src/session/runner/step.ts:77), [call-before-execute](repos/anomalyco__opencode/packages/core/src/session/runner/step.ts:131), [drain and join](repos/anomalyco__opencode/packages/core/src/session/runner/step.ts:165), [step settlement](repos/anomalyco__opencode/packages/core/src/session/runner/step.ts:262), [publisher ordering invariant](repos/anomalyco__opencode/packages/core/src/session/runner/publish-llm-event.ts:92), [delta coalescing](repos/anomalyco__opencode/packages/core/src/session/runner/publish-llm-event.ts:197).

The registry is Location-scoped and replays active transforms in registration order. Built-ins, configured/external tools and MCP share that boundary. An immutable effective catalog is captured per request. Model policy and whole-tool permission rules constrain visibility, and a Code Mode inventory can further group tools behind `execute`. A captured executor can still reach a live connection or refreshed services. Before and after hooks can repair or adapt calls. Runtime codecs decode model input and enforce declared output shape where supported. Tools normalize results for model or structured consumers and the session applies generic truncation. Shell and other producers may retain their own bounded excerpts and separately stored output. [Tool registration contract](repos/anomalyco__opencode/packages/core/src/tool/AGENTS.md:27), [snapshot and captured execution](repos/anomalyco__opencode/packages/core/src/tool.ts:301), [tool decoding and result contract](repos/anomalyco__opencode/packages/core/src/tool/runtime.ts:40), [hook execution and image handling](repos/anomalyco__opencode/packages/core/src/tool.ts:169), [truncation placement](repos/anomalyco__opencode/packages/core/src/session/runner/step.ts:150).

Authorization happens inside the leaf, after resolving its action and resources and before its side effect. The caller identity includes the Session, agent and source call. Explicit configured deny wins before saved allowances and hooks. Saved allow is project-scoped. An ask waits on a scoped, interruptible Deferred. Replies can grant once, persist an allowance or reject. Reject-with-feedback is a recoverable model-facing tool failure. Plain reject and form dismissal travel through leaf error mapping as dedicated defects, become typed declines in `SessionModelRequest`, and stop the step. The current classification at the outer lifecycle boundary loses that source, as measured in Section 5. [Permission identity](repos/anomalyco__opencode/packages/core/src/permission.ts:40), [effective evaluation](repos/anomalyco__opencode/packages/core/src/permission.ts:186), [interactive decision](repos/anomalyco__opencode/packages/core/src/permission.ts:257), [reply and saved policy](repos/anomalyco__opencode/packages/core/src/permission.ts:334), [question implementation](repos/anomalyco__opencode/packages/core/src/tool/plugin/question.ts:62), [step decline translation](repos/anomalyco__opencode/packages/core/src/session/model-request.ts:441).

MCP discovers tools, prompts and resources separately. A configured connection has a child scope, lifecycle lock, generation-checked callbacks and a bounded startup wait for inclusion. Local subprocess transport frames stdio and owns close and escalation. Remote sessions may reconnect on explicit session expiry. A stable MCP transform projects discovered tools into the same registry so refresh cannot change precedence over later overrides. Execution applies the leaf permission check, calls the exact server and tool, and normalizes structured, text and media outputs. Resource MIME handling can turn binary results into references. Connected clients and configured servers have explicit shadowing rules in the raw MCP catalog. A request's captured wrapper can still encounter a disconnected service and surface an ordinary tool failure. ### Durable state, events, retries and background work

The Bus allocates ordered sequence numbers per aggregate and uses SQLite transactions for the projection, sequence and optional stored event, plus an optional operational commit callback. WAL and a busy timeout support the local database implementation. A per-aggregate process mutex covers writes and post-commit notification. The canonical projections include Session, message, part and pending inbox tables. Stored full event payloads depend on the host's `events.persist` option. Projected state and local claims still persist with payload logging off. The durable log uses a captured replay cutoff, a `log.synced` marker and a scoped single-slot wake to tail via SQLite. The server's live SSE feed uses per-subscriber bounded queues, closes overflowing subscribers, and lets unconnected clients reconcile from service reads or the durable log if retained. [Database initialization](repos/anomalyco__opencode/packages/core/src/database/database.ts:35), [single event transaction](repos/anomalyco__opencode/packages/core/src/bus.ts:290), [atomic publishAll](repos/anomalyco__opencode/packages/core/src/bus.ts:538), [session log](repos/anomalyco__opencode/packages/core/src/bus.ts:809), [event feed](repos/anomalyco__opencode/packages/server/src/event-feed.ts:33), [SSE handler](repos/anomalyco__opencode/packages/server/src/handlers/event.ts:8).

Retries consider normalized provider errors, phase and delivery status, Retry-After, whether a response has emitted visible output, and whether stream continuation is safely recoverable. They update the durable retry schedule, then wait interruptibly. A pre-output retry can reuse the assistant ID. A post-output retry settles the earlier attempt and gets a fresh ID. Stateful WebSocket transport has one active exchange per Session, connection affinity at the post-hook endpoint and headers, and staged checkpoints committed only after the terminal exchange is consumed. Rejected incremental continuations may rebuild a complete request once. Explicitly rejected or pre-send failures can use HTTP fallback under bounded rules. Ambiguous send failure has its own delivery classification. The output-limit path can prompt to continue with smaller chunks and stops a repeated truncation streak. [Step retry decision](repos/anomalyco__opencode/packages/core/src/session/runner/step.ts:211), [retry state and policy](repos/anomalyco__opencode/packages/core/src/session/runner/retry.ts:32), [model backoff budgets](repos/anomalyco__opencode/packages/core/src/model-retry.ts:22), [output-limit logic](repos/anomalyco__opencode/packages/core/src/session/runner/llm.ts:346), [transport affinity](repos/anomalyco__opencode/packages/core/src/session/model-transport.ts:116), [checkpoint promotion](repos/anomalyco__opencode/packages/core/src/session/model-transport.ts:414).

A subagent is a child Session with a background Job. The tool checks agent mode, depth, parent ownership, permissions and optional model selection. The child starts with separate history at the parent's Location. A new child's first prompt is admitted without waking so the Job can own the start. Follow-ups to an active child steer it. The Job keeps a recovery descriptor and a stable notification ID. The child's execution binds the appropriate Job generation. Settlement releases the execution claim and writes the parent's completion outbox in the same database transaction. Delivery admits a synthetic steer idempotently, acknowledges the outbox, and can wake the parent unless it has staged a revert. Restart handles lost shell and other background work, reattaches eligible daemon-backed commands, and lets running subagent Jobs own the child recovery path. The restart budget is durable and charged before launching, so a fast child's report cannot skip its parent's accounting. [Subagent tool contract and child admission](repos/anomalyco__opencode/packages/core/src/tool/plugin/subagent.ts:109), [Job start and caller context](repos/anomalyco__opencode/packages/core/src/session/subagent-job.ts:17), [transactional report](repos/anomalyco__opencode/packages/core/src/session/execution/subagent-report.ts:131), [parent delivery](repos/anomalyco__opencode/packages/core/src/session/execution/subagent-report.ts:75), [restart control flow](repos/anomalyco__opencode/packages/core/src/session/execution/restart.ts:427).

## 4. Strengths

- **A recoverable work model exposed through ordinary API operations.** The durable inbox can accept work before a model is available and distinguishes steers from queued input. Commit callbacks keep operational claim/outbox rows consistent with durable events. Duplicate prompts, cross-session IDs, promotion concurrency, late wakes, takeover boundaries and restart accounting all receive dedicated tests. This is substantially easier to reason about than shared mutable model messages and nested ad hoc loops. [Inbox tests](repos/anomalyco__opencode/packages/core/test/session-prompt.test.ts:984), [coordinator tests](repos/anomalyco__opencode/packages/core/test/session-run-coordinator.test.ts:1), [crash and budget tests](repos/anomalyco__opencode/packages/core/test/session-execution.test.ts:397).
- **Provider complexity stays below an explicit orchestration interface.** A stable canonical protocol separates provider request construction, stream assembly, tool definitions and transport from persistent session decisions. The route compiler centralizes request middleware, validation, parsing and final-event contracts. The route tests combine recorded exchanges and synthetic protocol boundaries, including real local WebSocket fixtures. Multiple transport paths can share transcript lowering while preserving route-specific state. [Protocol contract](repos/anomalyco__opencode/packages/ai/src/route/protocol.ts:9), [executor middleware](repos/anomalyco__opencode/packages/ai/src/route/executor.ts:252), [terminal event requirement](repos/anomalyco__opencode/packages/ai/src/route/client.ts:318), [recorded runner path](repos/anomalyco__opencode/packages/core/test/session-runner-recorded.test.ts:50), [real transport tests](repos/anomalyco__opencode/packages/core/test/session-model-transport-live.test.ts:151).
- **History is a persistent, version-aware model input.** Native window replay, text fallback, part normalization, legacy row upgrading, and attachment handling share a common load path with explicit compatibility tests. ## 5. Weaknesses and evidence status

### R1. A plain rejection or dismissal is recovered as shutdown

**Reproduced defect, high priority.** Plain rejection of the built-in `read` permission and cancellation of the built-in `question` form stop the current step. Both sessions then record `session.execution.interrupted` with reason `shutdown`. The coordinator is idle after cleanup, yet SQLite retains the claim and the durable idle projection does not advance. On the next host boot the recovery sweep admits a restart notice and makes another model request for each. There was one pre-restart model request in each case and two total after restart. No one resumed these sessions explicitly. An explicit session stop takes the same model/permission fixture through reason `user`, clears the claim, advances the idle outcome, and stays at one request across restart. Rejection with feedback becomes a tool error and makes its intended continuation during the original host. [Permission reply](repos/anomalyco__opencode/packages/core/src/permission.ts:334), [form dismissal](repos/anomalyco__opencode/packages/core/src/tool/plugin/question.ts:87), [typed decline extraction](repos/anomalyco__opencode/packages/core/src/session/model-request.ts:441), [step exit](repos/anomalyco__opencode/packages/core/src/session/runner/step.ts:317), [terminal mapper and claim retention](repos/anomalyco__opencode/packages/core/src/session/execution.ts:50), [settled hook](repos/anomalyco__opencode/packages/core/src/session/execution.ts:155), [idle projection](repos/anomalyco__opencode/packages/core/src/session/projector.ts:838).

The underlying representation confuses an internal decision to stop with a host-level fiber interruption. Plain declines use `Effect.interrupt` after settlement, but only `SessionExecution.interrupt` sets the coordinator's user reason. An unexplained interrupt becomes shutdown. For a subagent the same terminal branch also skips the normal parent settlement report, a source-supported extension of this defect. Existing tests confirm the step's local abort and a coordinator's explicit user interrupt through different seams. They leave the combination uncovered. [Step decline regression baseline](repos/anomalyco__opencode/packages/core/test/session-runner.test.ts:5608), [runner test coordinator replacement](repos/anomalyco__opencode/packages/core/test/session-runner.test.ts:472), [execution terminal controls](repos/anomalyco__opencode/packages/core/test/session-execution.test.ts:63), [explicit user interrupt test](repos/anomalyco__opencode/packages/core/test/session-execution.test.ts:176).

### T1. A wake before its first claim can be lost on process death

**Design tradeoff with an observed fault-window consequence.** A child process returned its default prompt admission while an injected projector gate parked the execution immediately before claim commit. A real SIGKILL left the original inbox row intact. After reopening the database, a claim already committed before the crash recovered and ran, but the admitted item with no claim stayed pending. The design explicitly makes wake advisory and startup recovery scans claims and Job rows. The fault injection widens a real commit gap without estimating its production frequency. ### T2. Tool effects, local recovery and replay have different ownership guarantees

**Design tradeoff and source-supported risk.** Commit and recovery logic can prove that a tool was called or settled. A local external side effect and the completion record generally cannot be committed together. A crash after an effect and before settlement can leave an aborted tool record. Later responses can attempt the intended work again. File mutation documents the missing atomicity and recovery boundary. Some producers narrow the gap with recoverable descriptors and daemon lookup by call identity. The shell takeover path is an example, and the subagent outbox covers notification delivery. Neither SQLite aggregate order nor replay ownership prevents two distinct application hosts from owning a Session in an unsupported shared-database topology. Managed startup is an explicit precondition for single-owner recovery. ### T3. Liveness and capacity are uneven across scopes

**Source-supported risks.** Tool fibers are concurrent and the step waits for the provider and its tool fibers before classifying declines. This is valuable when completing interactions already in motion. A blocked sibling or an extension that ignores interruption can delay reaching a terminal outcome, even when an interrupt was acknowledged. Uninterruptible publication protects SQLite consistency and makes callback/storage time part of cleanup latency. The local coordinator does not itself schedule a global concurrency quota. The Socket read pump places frames on an unbounded queue while the consumer parses, projects and runs hooks. The public SSE feed bounds its event count, which protects a separate publisher/consumer boundary. Process-global transport state persists between exchanges for cache affinity. It closes on explicit remove, move, a reload-aware drain, error handling or host finalization. Rotation age is checked at the next exchange, so the per-Socket read timeout does not imply timed idle eviction. No throughput bottleneck or resident-memory growth rate is claimed from these code paths alone. The runner rebuilds frame-ready context on every step. An applicable compaction limits rows and indexed part/blob batches reduce storage overhead, but the history load materializes the window before the request pass drops images and unsupported media. An unknown context limit, disabled automatic compaction or re-expansion can create a large local workset. Separately, the app-owned custom SDK `instances` layer has an infinite TTL and the default idle sweep iterates the ordinary Location map. Large sets of long-lived private sharing keys deserve a measurable resource budget. The checkout supplies no basis for a capacity figure under realistic multi-tenant traffic. ## 9. Post-mortem and prioritized improvements

Three pressures explain the current design. Providers reward stable, reusable request prefixes and impose different tool and context rules. Local users need fluid steering, visible partial output and responsive interruption. A managed service must survive client disconnect, process replacement and shell handoff. These pressures create useful separations among the event journal, the durable projections, the process-owned coordinator and connection-local state. They also create boundaries where stale policy or lost provenance has outsized consequences. Maintaining each boundary's unit tests keeps local behavior reliable. The most valuable additional coverage exercises the joins. [Core runtime invariants](repos/anomalyco__opencode/AGENTS.md:210), [request prefix and instruction choices](repos/anomalyco__opencode/packages/core/src/session/context.ts:183), [transport and logical retry](repos/anomalyco__opencode/packages/core/src/session/runner/step.ts:237).

| Priority | Improvement and acceptance evidence |
| --- | --- |
| **P0 — Preserve stop intent through settlement** | Represent plain permission rejection and form dismissal as explicit step abort outcomes, retaining distinctions among user stop, Location rebinding and host shutdown. Use the same normalization in coordinator settlement, projected idle state and Job completion. Test real SDK interactions and a SQLite reopen for allow, feedback, decline, dismissal, explicit session stop, Location reload and actual shutdown. Verify one terminal outcome, correct claim/idle timestamps, and no restart call for intentionally stopped work. Exercise parent report delivery for a cancelled child. |
| **P1 — Bind budget and tool snapshot to the effective model** | Resolve the effective model once for a logical request before deriving model-dependent tool visibility, Code Mode instruction shape and budget. Distinguish selected preferences from the runtime model in trace data. Give measured prompt anchors model, variant and replay-window provenance. Invalidate the estimate on history re-expansion, and estimate the actual expanded prefix before sizing output. Extend local-wire tests to assert native windows, same-provider switches, hook substitution, proactive compaction and correct fallback. |
| **P1 — Make the acceptance/scheduling guarantee explicit** | Decide whether default resume requires durable wake intent. If so, persist it in the admission transaction and recover only those pending items that requested scheduling, with a deliberate rule for user interruption, later queue/steer mutations and a staged revert. Keep a fault-injection test at each commit boundary, including a process kill after the return of the accepted receipt. Preserve explicit admit-only prompts. If wake remains advisory, make the exact-ID replay contract clear to one-shot callers. |
| **P2 — Give long-lived owners resource budgets** | Add load controls around active exchanges, queue bytes, open idle sockets and private SDK keys. Keep the fast low-latency cache path and make eviction observable. Add tests with multiple independent Sessions, a slow consumer, a blocked tool finalizer and idle connections. Measure tool/provider overlap and full context materialization before adding a global cap so load policy can preserve independent task progress. |
| **P2 — Address external-tool recovery and stable naming together with extenders** | Document explicit-only replay or idempotency for side-effecting tools, and let recoverable tools record a correlation key before the external effect where supported. Alert on normalized MCP collisions within the MCP producer and identify both raw bindings. Preserve intentional plugin override semantics and stable names where possible. Make delivered acknowledgement explicit or retain a minimal delivery receipt so a retry cannot echo a new mode as old state. |
| **P2 — Make timing tests enforce ordering deterministically** | Drive producer completion and the waiting poll with an Effect test clock or a controlled notifier. Keep a local native smoke that covers real process and file boundaries. Replace the ambiguous 10-second video notice assertion with a causal readiness assertion. Evaluate whether cross-process durable polling should have a same-process notification fast path. |

The architecture is suitable for its current process-local ownership model and has strong evidence across ordinary credential-free flows. Prioritize the user stop/restart contract and model-consistency fixes before extending the same core into larger multi-host or higher-throughput settings. The bulk of existing durability, adapter and scoped ownership mechanisms should support those changes without replacing the main session loop.
