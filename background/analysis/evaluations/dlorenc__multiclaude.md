1. **Bootstrap a repository.** `repo init <url> [name]` checks daemon reachability, loads the persisted registry, chooses a tmux session name, clones, infers a fork from an upstream remote or `gh api`, and copies bundled templates. It creates supervisor and configured merge-queue or shepherd windows in the managed clone. The CLI starts providers and attaches output pipes before registering the repository and those agents. It then creates the separate `workspace/default` branch, worktree and interactive window named `default`, and registers it. An existing source clone outside the managed root can select the repository by origin URL. Local paths worked for the integration fixture with an explicit name. ## 3. Why the design works and its governing invariants

- **Different artifacts carry different kinds of progress.** A detached PTY owns live execution, a worktree owns uncommitted work, a Git ref owns committed local work, an upstream PR owns the shared review record, and `state.json` indexes these resources. The division makes daemon-only restarts inexpensive. It also means a real completion invariant must relate the specific generation of all these resources. Registry presence and a window name alone establish much less. The warm-restart control kept the same supervisor process and session ID after SIGKILL of the daemon. [State record](repos/dlorenc__multiclaude/internal/state/state.go:144) [Existing-session restore](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1754) [Process lookup](repos/dlorenc__multiclaude/pkg/tmux/client.go:341)
- **A worktree is a useful edit boundary.** Branch-specific directories and indexes permit parallel edits and familiar Git repair. Their repository and remote refs, object database and stash namespace remain shared. Persistent service agents can share the managed clone itself. Safe background Git operations require either a repo-scoped lock across the full sequence or stable identities for the individual refs and stash objects they operate on. [Worktree creation](repos/dlorenc__multiclaude/internal/worktree/worktree.go:52) [Persistent path selection](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1602) [Stash and rebase](repos/dlorenc__multiclaude/internal/worktree/worktree.go:815)
- **A bounded single-user trust model makes local integration simple.** The Unix socket is mode 0600. Normal daemon state mutations run under an RWMutex, publish through a same-directory temporary file and rename, and background readers generally take copied snapshots. This protects the JSON view against half-written state under ordinary process interruption and some concurrent reads. It relies on a single logical writer and consistent ownership at the method boundary. Disk sync, multi-step transactionality and an exclusive cross-process lock are separate properties. [Socket bind and mode](repos/dlorenc__multiclaude/internal/socket/socket.go:101) [State write](repos/dlorenc__multiclaude/internal/state/state.go:212) [Deep snapshot](repos/dlorenc__multiclaude/internal/state/state.go:353) [PID claim](repos/dlorenc__multiclaude/internal/daemon/pid.go:81)
- **The external ratchet lets people and models coordinate loosely.** Workers can start immediately and publish incremental PRs. The supervisor explicitly prefers redundant exploration to blocking. Review, CI and protected branch rules can serialize adoption of desirable changes even when intermediate work overlaps. This is an effective design choice for a local, trusted operator with a safe upstream branch policy. It requires explicit capacity and merge rules if the objective shifts toward cost guarantees, deadline scheduling or predictable policy enforcement. [Design philosophy](repos/dlorenc__multiclaude/DESIGN.md:5) [Supervisor overlap policy](repos/dlorenc__multiclaude/internal/prompts/supervisor.md:59) [Review gates and merge](repos/dlorenc__multiclaude/internal/templates/agent-templates/merge-queue.md:13)
- **A durable file and a terminal notification are different acknowledgments.** Mail is inspectable without the daemon, and pending records can be retried on the next scan. The accepted Unix response signifies a scheduled routing attempt. Successful tmux command execution signifies input was handed to a PTY. A manually read or acked mailbox file records the strongest acknowledgment the daemon has here. Durable processing would additionally need a stable message ID delivered to the receiver with a monotonic transition and replay strategy. [Message states](repos/dlorenc__multiclaude/internal/messages/messages.go:13) [Asynchronous trigger](repos/dlorenc__multiclaude/internal/daemon/daemon.go:677) [Delivery and status order](repos/dlorenc__multiclaude/internal/daemon/daemon.go:397)

## 4. Strengths

- **Small operational footprint with manual recovery points.** A Go binary, tmux, Git and the provider CLI support detached execution without an additional DB, queue service or provider service adapter. A human can inspect the PTY, worktree, branch, log or mailbox directly and continue with standard tools. Real tmux and a local provider stand-in confirmed detachment from the daemon, message delivery and normal cleanup. - **Separation of the interactive workspace and project services.** The default workspace gets a durable worktree and separate conversation and avoids automated wakes and message injection. Supervisor, merge queue and shepherd roles provide different feedback and control loops around shared work. Dedicated worker branches preserve a clean unit for review and allow a task to start at a specific named ref. The low-level Git fixtures exercised actual local fetch, dirty-change preservation in serial operation and conflict paths. Merged-branch cleanup refreshes remote refs and checks checked-out worktrees before deleting local branches. The tests also show where these safety checks stop. ## 5. Weaknesses and evidence status

### Highest-impact findings

1. **Cleanup can erase uncommitted work, including through a command advertised as a dry run.** A missing worker window is interpreted as permission to settle the task. The daemon records history, kills the window if possible, removes the agent, then runs forceful Git worktree removal with no dirty-data gate. A real worker fixture had one modified tracked file and one untracked marker. Interactive removal left both in place when declined. Closing the window and running the health path removed the checkout, left the branch, and wrote an `unknown` task history record. The CLI's `cleanup --dry-run` sends `dry_run` on the live daemon path, but the handler unconditionally runs health reconciliation. In a separate fixture, the command printed that no changes would be made and removed an untracked marker with its checkout. Explicitly completing a task also triggers this destructive path. The hibernate path is a separate failure: it stores `git diff HEAD` and a list of untracked names, then force-removes the worktree. The fixture's tracked text was recoverable from the patch and the untracked bytes were absent. Archive write errors do not consistently gate removal. [Missing-window decision](repos/dlorenc__multiclaude/internal/daemon/daemon.go:324) [Force removal](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1414) [Dry-run CLI](repos/dlorenc__multiclaude/internal/cli/cli.go:4822) [Daemon dry-run handling](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1163) [Interactive check](repos/dlorenc__multiclaude/internal/cli/cli.go:2933) [Hibernate archive and teardown](repos/dlorenc__multiclaude/internal/cli/cli.go:3123)
2. **Branch retirement proves the wrong ref.** The cleanup sweep fetches the selected upstream and uses `git branch --merged <upstream-ref>`, which examines local branches. After excluding checked-out branches, it force-deletes those local branches and attempts an unconditional deletion of the matching name on origin. The shared branch name does not prove origin still points to the same commit. In a bare-file-remote fixture, origin's worker branch was one unmerged commit ahead of the stale local branch. Cleanup returned success and the bare remote no longer advertised the branch. A checked-out control branch was kept. The commit object was still readable locally, so the demonstrated effect is ref loss and loss of normal branch discoverability. Reachability can change with Git retention and garbage collection. 3. **Concurrent refresh can move private edits into the wrong checkout.** The worktree helper stashes tracked and untracked changes, rebases, then pops the top stash. Linked worktrees share that stack. With A and B held just before their real rebases, A popped B's stash and B popped A's. Both reported successful restoration and the final stash list was empty. Serial calls preserved both sets of edits. The Go daemon can overlap explicit refresh requests with one another or with the periodic pass. The same shared stack also allows interference from an agent running Git itself. ### State, coordination and operational failure modes

- **Acknowledgment and input delivery can diverge.** Two overlapping router passes can both read one pending ID and both send it. The controlled fixture received identical text twice from a single durable message. Separately, an ack that occurs after the router's snapshot can be overwritten as delivered with `acked_at` still set. Both paths are possible because state transitions are plain read/modify/write with no version check or exclusive claim. JSON is written in place, invalid files are silently skipped by listing, and status advancement follows I/O to a terminal. The tmux method described as atomic uses three CLI calls joined by shell `&&` and a server-wide unnamed buffer. Forcing an interleave delivered B's marker to both A and B, even though both calls returned success. A serial control delivered both to the correct windows. The same method supplies the initial CLI worker task. With normal concurrent worker creation, 16 live workers and 16 successful CLI calls produced only 9 correctly assigned task lines in the first trial and 10 in each of four additional 16-way trials. The serial control delivered every task correctly. State contained the intended assignments even when the provider observed the wrong one. [Router](repos/dlorenc__multiclaude/internal/daemon/daemon.go:372) [Message status update](repos/dlorenc__multiclaude/internal/messages/messages.go:98) [In-place update](repos/dlorenc__multiclaude/internal/messages/messages.go:175) [Shared paste buffer](repos/dlorenc__multiclaude/pkg/tmux/client.go:315) [Initial task send](repos/dlorenc__multiclaude/internal/cli/cli.go:5899)
- **Persistence serializes writes without making transitions atomic.** `AddAgent` inserts before saving. With a directory placed at the state-file target, it returned a rename error yet left an in-memory agent. After restoring the previous file, retry was rejected as duplicate, and a different successful save published the phantom. A successful nudge writes its entire stale agent value back and can overwrite a more recent PID. The barrier test saw PID 202 revert to 101 in both memory and a fresh disk read. The separate repo-config race is a Go memory race: `GetRepo` exposes a live pointer after unlocking, and concurrent getters and setters touched the same config storage. The focused race detector reported the exact production read and write lines. An independently built race-enabled daemon reproduced the same race over real Unix connections with 100 successful requests from each side. Two concurrent cleanup passes also appended duplicate history rows for the same worker generation. A malformed multi-field config request also committed its first valid update before rejecting a later field. Turning the setting off left the actual queue pane running. Removing a selected repository also left a durable current-repository pointer to the removed row. An explicit unset repaired the pointer. [AddAgent mutation](repos/dlorenc__multiclaude/internal/state/state.go:387) [Nudge writeback](repos/dlorenc__multiclaude/internal/daemon/daemon.go:479) [Pointer exposure](repos/dlorenc__multiclaude/internal/state/state.go:278) [Racing read](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1269) [Racing write](repos/dlorenc__multiclaude/internal/state/state.go:514) [Repo removal](repos/dlorenc__multiclaude/internal/state/state.go:287) [Current selection](repos/dlorenc__multiclaude/internal/state/state.go:337) [Partial config writes](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1324)

## 9. Post-mortem and highest-leverage improvements

### Root-cause post-mortem

The design optimizes deployment and time to first parallel work. It delegates project planning to Claude, execution to supervised terminals, and integration to GitHub. That makes sense for a single developer who can see the work and intervene. A window, worktree, JSON file and Git branch each have simple local semantics. The orchestration pressure arrives when the product composes those operations across independent processes and then treats the success of one step as the whole operation's success. The largest failures arise at those transitions. [Deployment philosophy](repos/dlorenc__multiclaude/DESIGN.md:5) [tmux rationale](repos/dlorenc__multiclaude/DESIGN.md:17) [Worktree rationale](repos/dlorenc__multiclaude/DESIGN.md:39) [JSON rationale](repos/dlorenc__multiclaude/DESIGN.md:123)

- **Identity was initially a convenient name.** A repository and human-readable agent name now select multiple artifacts whose lifetimes differ. Window names stand in for provider generations, pane shell PIDs stand in for child ownership, and a global agent-named file stands in for a particular role and configuration version. The same substitution appears in remote cleanup, where a branch name maps a merged local ref to a potentially different remote ref. Mutable names cannot supply the identity proof required for restart, delivery or deletion. [State identity fields](repos/dlorenc__multiclaude/internal/state/state.go:144) [Pane PID](repos/dlorenc__multiclaude/pkg/tmux/client.go:343) [Prompt reopen](repos/dlorenc__multiclaude/internal/daemon/daemon.go:2164) [Remote branch cleanup](repos/dlorenc__multiclaude/internal/worktree/worktree.go:518)
- **The happy path accumulated alternate writers and recovery paths.** Fresh init, custom spawn, explicit restart, health restart and cold restore choose different conventions. Named workspace provisioning advanced to `default` while cold reconstruction retained `workspace`. Generic restore delegates role re-creation to a supervisor, adding an eventual model decision in a path where deterministic inventory restoration matters. Recovery implicitly assumes the latest tests exercised real provider readiness and current workspace naming. Test mode and manually assembled fixtures often avoid both. [Fresh default](repos/dlorenc__multiclaude/internal/cli/cli.go:1514) [Cold reconstruction](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1817) [Generic start in test mode](repos/dlorenc__multiclaude/internal/daemon/daemon.go:2054) [Recovery fixtures](repos/dlorenc__multiclaude/test/recovery_test.go:363)
- **Thread safety grew around data containers.** The snapshot and mutex work solves some map iteration and publication hazards. It does not claim an operation before terminal or Git I/O, validate generation at writeback, or settle only after external effects succeed. Periodic checks and fast manual RPC triggers create more overlap on the same underlying resources. As a result, a clean race run can coexist with a deterministic wrong-recipient or wrong-stash result. The focused config test also shows where the container lock still leaks. [State snapshots](repos/dlorenc__multiclaude/internal/state/state.go:353) [Loop triggers](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1091) [Router side effects](repos/dlorenc__multiclaude/internal/daemon/daemon.go:397) [Refresh stash](repos/dlorenc__multiclaude/internal/worktree/worktree.go:815)
- **Cleanup and introspection favor forward progress and simple status.** Product prompts encourage work to be expendable once a PR exists. The teardown path has no machine-checked evidence that work is published or recoverable. Detached start and stop return early with reassuring messages. History and rich status assign simple display states where observations are incomplete. The documented proposal for hibernated persistence would require new desired-state data and a restore path. It is design context only. The runtime hibernate command is an archive-and-remove action. [Worker finish instructions](repos/dlorenc__multiclaude/internal/templates/agent-templates/worker.md:15) [Cleanup order](repos/dlorenc__multiclaude/internal/daemon/daemon.go:1414) [Detached return](repos/dlorenc__multiclaude/internal/daemon/daemon.go:2283) [Hibernation proposal](repos/dlorenc__multiclaude/openspec/changes/add-repo-lifecycle/specs/repo-lifecycle/spec.md:52) [Actual archive](repos/dlorenc__multiclaude/internal/cli/cli.go:3113)
